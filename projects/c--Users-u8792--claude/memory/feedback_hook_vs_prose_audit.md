ルール/挙動を「Hook（settings.jsonの.ps1で機械強制）」にするか「文章のまま（CLAUDE.md/スキルに残す）」にするかの判断原則。

**Why:** 2026-06-08にCLAUDE.md+39スキルを41エージェントのWorkflowで監査した結果、明確にHook化すべきものは0件、BORDERLINEが9件だった。既存8フックが機械強制領域を既にカバーしており、環境は既にほぼ理想的だった。「Hook候補に見えても実は文章に残すべき」が大半。

**How to apply:**
- **Hookにする** = (a)「○○したら必ず/前後に必ず」の自動実行・機械強制 かつ (b)シェル/正規表現で機械判定可能 かつ (c)Claudeの文脈判断が不要。例: 危険コマンドブロック、機密ファイル保護。
- **文章のまま残す**（=CLAUDE.md/スキル） = Claudeの判断・文脈理解・設計方針が要る、または知識・手順・規約。例: クイズ出題（着手直前かの判定が文脈依存）、Web取得のフォールバック判断。
- **Hook化が"むしろ害"になるパターン（重要）:**
  - main/masterで実装ブロック系 → ~/.claude自身がmain上でauto-pull/pushする運用と衝突し全編集を誤ブロック
  - Prettier/tsc等の整形をグローバル(~/.claude)に置く → 未導入リポジトリでエラー多発
  - HTML2MB超警告・console.log除去・frontmatter検証 → 拡張子/パスだけでは対象を機械判定できず誤発火
  - 「機密データを含むか」「実装の開始か」など中身・意図の判定 → 正規表現で不能
  - 適用対象が極端に狭いニッチルール → 全Bash/全Editにグローバルフックを足すのは過剰
- 迷ったら**文章寄りに倒す**。誤発火コストが便益を上回るならHookにしない。
- 監査は提案→承認→実装の順。誤移譲を防ぐため候補一覧をユーザーに見せてから実装する。

**用語メモ:** 自分は当初これを英語で「Prose（散文＝コードでなく自然言語の指示）」と呼んだが、ユーザーに伝わらなかった。日本語では「文章のまま残す」「CLAUDE.md/スキルに残す」と表現する。専門用語を訳さず使わない。
