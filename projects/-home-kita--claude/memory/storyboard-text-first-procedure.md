★★ユーザー恒久手順（2026-07-13 指示「次からこの手順でstoryboardを作って」）。動画のstoryboardは必ずこの順で作る（video-media-studio スキルの storyboard フローを、この具体規律で運用する）。

**★2026-07-17 ユーザー指示で工程を改訂（正本は SKILL.md「動画生成フロー」＋ `reference/directing-board.md`）**: 字コンテと動画生成の間に**演出ボード（鉛筆モノクロのラフ画＋色矢印）の承認ゲートを新設**。用語は3層（字コンテ＝テキスト / 演出ボード＝鉛筆ラフ・ゲート2・**参照として動画生成に渡す** / キーフレーム画像＝フォトリアル・i2v入力）。**参照画像が揃っていても演出ボードは省略しない**（省略できるのはキーフレーム画像だけ）。矢印凡例（赤=身体/青=カメラ/緑=フレーミング/橙=光/黄=VFX/黒文字=レンズ注記）は**字コンテ作成時に定義する**。以下の旧手順は、この改訂を前提に読む:

1. **実世界の工程/仕組みが不確かなら、まず Codex に確認して正確にする**（例: バーテンダーの本物のシェイク工程＝材料はグラスでなくシェーカーのティンに入れる→氷→密閉→両手でシェイク→濾してグラス）。推測で描かない。
2. **テキスト storyboard を先に作る**（画像より先）。各カットに **番号 / タイムスタンプ（0–4s 等）/ VISUAL（映るもの・道具・構え）/ ACTION（動作）/ AUDIO** ＋ **共通STYLEブロック** ＋ **メタ（総尺/形式9:16/音/参照）**。Seedance/i2v は1クリップ4秒以上なので**カットは4秒刻み**が無難。**★総尺は生成モデルの1回上限（AtlasCloud Seedance i2v/r2v=15秒）以内に設計する（2026-07-13 ユーザー確定・SKILL.mdにも設定）**: 「1本もの（継ぎ目なし）」で作るなら**総尺≤15秒**。超えると多クリップconcat（つぎはぎ）か延長（継ぎ目/ドリフト）が要るので、最初から15秒以内に収める。
3. **ユーザーに提示して承認を得る（ゲート1）**。承認前に画像/動画を作らない。

3b. **★演出ボード（鉛筆モノクロのラフ＋色矢印）を Codex で生成し、承認を得る（ゲート2・2026-07-17 新設）**。カット数＝字コンテのカット数（1カット＝1パネル）。**参照画像が揃っていても省略しない**（省略できるのはキーフレーム画像だけ）。**フォトリアルにしない・リアル化スターターを足さない**（リアル既定の対象外）。番号・秒数・矢印・各パネルの注記は**焼き込む**（「画像内に文字を入れない」恒久ルールの対象外＝ボードは納品物でなく設計図）。**★凡例（各矢印の"説明"）はボードに描かない＝字コンテ側で定義する**（2026-07-17 ユーザー指示。GPT Image は放置すると凡例ストリップを描くので `Do NOT draw a legend...` を明示）。承認後は**ボード画像も r2v の参照に入れる**（ユーザー確定）。実機検証済みの定型は video-media-studio `reference/directing-board.md`。**字コンテの承認はボードの承認ではない。**
4. **承認後の生成は2経路（★2026-07-14 ユーザー確定・SKILL.md反映済み）**: **経路A（推奨・既定）＝参照人物がある同一人物・新シーンは、キーフレーム画像を作らず reference-to-video で「参照＋テキスト絵コンテ」から"直接"生成**（キーフレーム→i2vのつぎはぎ感/工数を省ける。★**総尺≤15秒はショット毎に分けず"1回で"まとめて生成**＝ショット別生成は背景・人物がショット間でドリフトするため（2026-07-14 ユーザー確定）、カット/アングル切替も1プロンプトに記述。★**音声(ASMR/環境音)もSeedanceが動画と同時生成=後付け不要**。SFW/水着=AtlasCloud Seedance `reference-to-video`、NSFW=wan-2.7 ref系/ローカルHunyuanCustom。「手で胸を揉む」等の複雑相互作用で破綻したら経路Bへ→[[hunyuancustom-r2v-nogo]]）。**経路B（フォールバック）＝キーフレーム画像→i2v連鎖**（参照が無い/開始終了画やカット尺を精密に制御したい時。下記4a–4d）。★ベース参照の確認(4a)は経路Aでも必須。 **経路Bで画像 storyboard を作る場合は**★**各パネルに秒数ラベル（「① 0–4s 動作」等）を焼き込み、テキストと1対1で対応**させる（ラベル無しの2x2は「どれが何秒か分からない」とNG＝2026-07-13指摘）。ラベルは Noto Sans CJK JP で drawtext。
   - **★4a. 画像を作る前にベース参照を確認（2026-07-13 ユーザー確定・SKILL.mdにも設定済み）**: storyboard画像を生成すると、そこに写る人物＝以後の動画の人物が確定し**後で変えられない**（動画はこのstoryboardを土台にi2v化する）。候補参照が複数あるなら、**着手前にどれをベースにするか必ずユーザーに聞く**（勝手に1枚選んで作らない）。実例違反: 長谷川#1/#3/#5の3枚採用済みなのに私が黙って#5でstoryboardを作り、後から「選んで」と聞いた＝順序が逆。
   - **★4b. 「storyboard画像を作って」＝キーフレームで構成されたボード（2026-07-13 ユーザー確定・SKILL.mdにも設定済み）**: 各パネルは捨てるモックでなく、**動画のi2vにそのまま使える実キーフレーム**。動画の最終アスペクト比（縦9:16等）で生成し、複数参照を混ぜず**1つのベースで全パネルの同一性を揃える**。
   - **★4c. 実装（2026-07-13 実証・キーフレーム間の統一感の作り方）**: **t2i単独（参照なし）は各キーフレームで顔がドリフト**する。**全キーフレームを"同一の人物リファレンス"から生成すると顔が統一される**（ユーザー洞察「リファレンスをボードに入れると統一感」＝正）。9:16＋参照の実装＝AtlasCloud **`bytedance/seedream-v4.5/edit`** に共通人物ref（`--image`）＋**`--size 1440*2560`**（9:16の2K）。★AtlasCloud seedreamは無検閲寄りで**cleavage参照も通る**（Codexは"sexualized"で拒否＝NSFW参照不可）。`cloud_atlascloud.py` の cmd_image に `--image`(→`images`), cmd_video に `--reference-image`(→`reference_images`最大9枚) を追加済。
   - **★4d. 動画を"1本もの"で作る（つぎはぎ感を消す）**: 4カットを別々i2v→concatは**つぎはぎ感が出る**（ユーザー指摘）。対策＝**seedance-2.0/reference-to-video に統一キーフレームを reference_images で複数入れ、"image 1..N を順に"のシーケンスを1プロンプトで duration 15秒 1回生成**（カット無し）。リスク=4動作の順序/構図が崩れ得る（Codex警告）。ダメなら各カットi2v＋クロスフェード。★r2v/i2vは「動く写真」化しやすい→プロンプトに"LIVE VIDEO, she moves continuously, not a frozen photo"を明記。
5. **参照＋スキルのリアル質感・シネマを"ふんだん"に**: キャラ/人物リファレンス画像＋ペルソナ設定＋関連素材（カクテル等）を元に、realism-naturalization（毛穴/実カメラ/no-CG）＋シネマティック（アナモルフィック・浅い被写界深度・実用光＋リム・フィルムグレイン・カラーグレード）を効かせる。
6. **カメラの"動き"（dolly/pan/tilt/orbit等）を"写実的に描画"するのは動画段階**（フォトリアルのキーフレーム静止画にはモーションブラー等を入れず、構図/光/質感だけ）。**★2026-07-17 改訂: ただし演出ボード（鉛筆ラフ）の上では青矢印で必ず"図示"する（図示≠描画）。** この項目を根拠にボードから青矢印を排除しない（実測: エージェントがこの記憶を引用してカメラ矢印を排除した）。
7. 画像モデルは Seedream（`cloud_openrouter.py image`・bytedance/seedream）、動画は SFW=Seedance / NSFW=wan-2.7-spicy。**Seedance/Seedream を混同しない**（Seedance=動画、Seedream=画像）。

**継続性(continuity)チェック（必須）**: ストーリーに存在しない小物が映り込んでいないか毎パネル目視する。例: 「カクテルを作る途中」なのに完成カクテルグラスが置かれていた（NG＝矛盾）。★原因は**参照画像(カクテル＝グラス入り)を渡すと、その小物/構図ごと再現される**こと。**特定の属性(色など)だけ欲しいときは画像参照でなく文章で指定**し、不要な小物混入を防ぐ＋プロンプトに「〇〇は出さない」「Avoid: 〇〇」を明示する。人物の同一性用の参照は渡してよいが、小物入りの参照は要注意。

**「リアル感」＝人間の肌のリアル感を最優先**（[[realism-naturalization-default-on]]）。storyboard/動画/画像でリアルを求められたら肌質感(毛穴/subsurface/皮脂の艶/no plastic-doll skin)を最強度で効かせる。

**違反履歴（2026-07-13）**: (a) テキスト承認前にいきなり2x2画像を作った (b) 秒数ラベルが無く対応が不明 (c) 工程を間違えた（素材をカクテルグラスに注ぐと描いた＝正しくはシェーカーのティン） (d) ストーリーに無い完成カクテルグラスが映った(参照画像由来・継続性見落とし) (e) 肌のリアル感が不足。→ 本手順＋上記チェックをルール化。
