「日本語校正して」と頼まれたら、**診断パス → 校正パス**の2段で行う（ユーザー指示 2026-08-31・恒久）。

**Why:** 「係り受け・冗長・表記ゆれを直せ／行数を変えるな・文字数を増やすな」という校正の依頼だけでは、**前段の問いに答えていない段落・既出情報を言い直しているだけの文・直前の記述と食い違う自己言及**を構造的に直せない。これらを直すには文を削り段落をまたいで主張を移す必要があり、行数固定の制約がそれを禁じてしまう。実際に科研費S-61で、「基課題がもともと扱ってきた」と書いた対象を次の段落で「本研究が選ぶ」と書く矛盾と、前段の「どこで検証するか」という問いに次段が「何を検証するか」で答える問いと答えのズレが、校正パスを2回通しても残りユーザーに指摘された。

**How to apply:**

1. **診断パス（先）** — 下のプロンプトで Codex（または別モデル）に投げる。**ファイルを書き換えさせず、指摘レポートだけ返させる。行数・文字数の制約は課さない**（頁調整は指摘採用後に自分でやる）。返ってきた指摘は自分で事実照合してから採否を決める。
2. **校正パス（後）** — 構造を直し終えてから、係り受け・冗長・表記ゆれの校正をかける。ここでは行数固定・文字数上限の制約をつけてよい。

診断用プロンプト（そのまま使う。対象ファイルと様式の観点だけ差し替える）:

```
（文書名）を診断してください。校正（誤字・係り受け・冗長の修正）ではありません。
ファイルは書き換えず、指摘レポートだけを返してください。

対象: （ファイル一覧）
読み手: （誰が読むか。専門外を含むならそう書く）
評価の観点: （その文書が何で評価されるか）

■ 段落ごとに次を判定する
1. この段落が担う主張を1文で書き出す。書き出せない段落は「主張不明」として挙げる。
2. 直前の段落の最後の文と、この段落の最初の文の接続が成立しているか。
   特に、前段が問いで終わっているのに次段が別の問いに答えている「問いと答えのズレ」を探す。
3. 段落内で論理が飛んでいる箇所（AだからB、が成立していない箇所）。

■ 文ごとに次を判定する
4. この文を削ると何が失われるか。失われるものが無ければ「削除候補」として挙げる。
5. 既に述べたことを言い直しているだけの文（re-announce）。
6. 文書内の他の記述と食い違う文。特に、直前で「もともと扱ってきた」と書いたものを
   「本研究で新たに選ぶ」と書くような、自己言及の矛盾。
7. 指示対象が一意に決まらない語（「国内」がどの国か、「検証対象」が何の検証か等）。
8. 専門外の読み手が初出で意味を取れない語。

■ 出力形式
指摘ごとに次の4点を、重要度の高い順に並べる。
  - 場所（ファイル名と行番号、該当文を引用）
  - 何が問題か（上の1〜8のどれか）
  - なぜ問題か（読み手にどう読まれるか）
  - 書き換え案（削除を勧める場合は「削除」と書く）

問題が無い段落は「問題なし」と1行で書き、無理に指摘を作らない。
指摘の数を稼ぐために軽微な文体の好みを混ぜない。
日本語で回答してください。
```

4 の「この文を削ると何が失われるか」を全文に強制するのが肝で、これが「仕事をしていない文」を機械的にあぶり出す。

## 診断パスに足す観点：「流れ」（2026-09-01 追加）

構造の診断（上のプロンプト）を通しても、**文と文・段落と段落のつなぎ目**は残る。科研費S-61でユーザーが自力で見つけ、こちらが見落としていた型が次の3つで、いずれも「文単位では正しいが、置かれた場所が悪い」ために起きる。

1. **結論・固有名詞が理由より先に出る** — 「渡航先はDuke-NUS…、海外共同研究者はA/Prof Nan Liuである。」が前後と接続せず唐突だった。**理由→結論**に組み替える（「この計画には〇と△の両方が要る。その二つが揃うのが…」）。機関名・人名・手法名が初出する箇所は全部この観点で点検する。
2. **問いと答えのズレ** — 前段が「多民族で検証する場を**どこに**求めるか」と締めているのに、次段が「検証**対象**は骨折である」と答えていた。前段が立てた問いと次段が答える問いが一致しているかを、段落の境目ごとに確認する。
3. **定義より先に用語を使う／見出し1つに段落1つ** — 「設置条件」を使ってから次節で定義していた。また見出し「なぜ設置条件なのか」が段落1つしか抱えておらず、見出しが機能していなかった。定義→使用の順に直し、見出しは複数段落をまとめる単位にする。

診断プロンプトの「文ごとに次を判定する」に、次を足して使う。

```
- 結論や固有名詞（機関名・人名・手法名）が、その理由や必要性より先に唐突に出てくる箇所。
- 前段が立てた問いと、次段が答えている問いが食い違っている箇所。
- 定義より先に使われている用語。
- 見出しと配下の段落の対応（見出しが内容を予告できているか、見出し1つに段落1つになっていないか）。
```

## 校正まわりで実際にはまった落とし穴（同上）

- **校正器に「行数を変えるな・文字数を増やすな」と縛ると、構造的欠陥は直せない。** Sonnet 5 は5ファイル中3ファイル無変更で返した。制約を外した診断パスを別に立てる（本文冒頭の手順）。
- **本文の言い回しが変わると、それに依存した仕掛けが黙って壊れる。** 図の挿入位置を「特定の文の書き出しに一致したら」で指定していたため、校正で文頭が変わって図が1枚消えた。→ [[office-docx-is-the-source]]
- **略語は使用回数を数えてから決める。** 「UKA」は文書全体で4回・概要では1回しか使っておらず、略語化の価値がなかった（全廃してフルスペルに）。1〜2回ならフルスペルのまま書く。
- **「国内」「海外」は主語となる国を明示する。** 日本の話かシンガポールの話か読み手が判断できない。文書全体を grep して一括で「日本国内」に揃えた。
- **既存の事実（基課題など）を狭く言い切らない。** 外部データベースで照合できる対象（科研費の課題名など）と食い違うと信用を失う。狭める場合は本人に事実確認する。
- **概要と本文の重複は冗長ではない。** 様式が「冒頭に概要を簡潔にまとめ、本文には…」と要求している場合、重なるのが前提の構造。抄録と本文の関係と同じ。
- **弱みとして書かれている事実を、環境の制約として書き換える。** 「基課題は力学量を扱えない」（＝基課題の欠陥に読める）→「この基盤は日本人のデータで動いている。他集団で成り立つかは日本国内では確かめようがない」（＝渡航の必然性の論拠になる）。
