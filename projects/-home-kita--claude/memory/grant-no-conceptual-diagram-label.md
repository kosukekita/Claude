助成金・研究費の申請書を書くときの恒久ルール（ユーザー指示 2026-08-23・複数回の指摘を経て確立）。
CLAUDE.md「常にやる」から参照される詳細版。

**Why:** 分量制限のある書類で、読み手に何も足さない語に行を使わない。断り書きに使う一行は主張に使う。

**How to apply:** 以下をそのまま適用する。★は実際に違反して指摘を受けた項目。

**🔴 申請書に「概念図」と書かない（ユーザー指示 2026-08-23・複数回の指摘を経た恒久ルール）**: 助成金・研究費の申請書では、図のタイトル・パネルの小見出し・注釈のいずれにも「概念図」「イメージ図」「模式図」「※ イメージです」と書かない。**実データでない図がそうであることは審査員には自明**であり、断り書きは紙幅を食うだけで情報を足さないからである。実測結果の図と区別を付けたいときは、概念側に注記を足すのではなく、**実測側に「実解析結果」と書いて区別する**（情報が増えるのは実測側の一言だけで済む）。対象は本文にとどまらず、図の中のテキスト、図を生成するスクリプトが**描画する文字列**（`build_fig*.sh` の `--prop text=`、matplotlib の `ax.text` など）、Claude Design 等へ渡す図版プロンプトまで含む。スクリプト内のコメントや docstring は画像に出ないので対象外。書き終えたら `grep -rn "概念図\|イメージ図\|模式図" <申請フォルダ>` と、docx から抽出した本文テキストの両方で確認する（grep のヒットは描画文字列かコメントかを見て仕分ける）。同じ理由で、読めば分かることを断るメタ表記（「以下に述べる」「本節では〜を説明する」「※あくまで一例」）も申請書では削る。分量制限のある書類では、断り書きに使う一行を主張に使う。

**🔴 ネガティブとポジティブの線引き（ユーザー指示 2026-08-23）**: 「申請書にネガティブを書かない」は**機械的な禁止語の除去ではない**。削るのは**自分の計画の弱みと不確実性**であって、ネガティブに見える事実すべてではない。

| 扱い | 例 |
|---|---|
| **削る**（計画の弱み・不確実性） | 「現時点では確定していない」「連携が立たない場合も」「帰国後の課題とする」「未発表」「様式が求めていないリスクと対策の欄」 |
| **残す**（解いた課題の説明） | 「5つの値の組み合わせを網羅できない → そこでサロゲートを作った」。弱みではなく成果の前振り |
| **残す**（留学・助成の必要性） | 「この規律は国内では得がたい」「国内では人材が不足している」 |
| **残す**（要件充足を裏づける事実） | 受入条件が「Research Fellow（無給）」であること。**無給だから助成が要る**というポジティブ要因であり、募集要項の年間収入要件を満たす証明にもなる |

ネガティブに見える事実が申請の追い風になることがあるので、語だけを見て消さない。**そして、この線引きに自分で例外を作らない**——「これは手続きの説明だから残してよい」と独断で判断して、実際にユーザーから再指摘を受けた。迷ったら消すか残すかをユーザーに確認する。

**🔴 申請書に「未発表」と書かない（ユーザー指示 2026-08-23）**: 「未発表」「予備的」「試験的」のように自分の成果を弱く見せる語を、聞かれてもいないのに添えない。書かなければ済むものをわざわざ書けば、限られた紙幅を使って自分の評価を下げることになる。同じ理由で、**様式が求めていない「リスクと対策」のような欄を自発的に作らない**。項目を立てる前に募集要項と様式の指定（「文字サイズ11、最長2頁」等しか書かれていないことが多い）を読み、財団が要求している項目かを確かめる。求められていないなら、その紙幅は新規性と意義に使う。あわせて「仕事」のような口語は「研究」に直す。

**🔴 本文だけ直して図を見落とさない（同日・実際に起きた事故）**: 用語統一や表現の修正は、**図の中のテキストと、図を生成するスクリプトが描画する文字列**まで必ず及ぼす。本文の「破壊解析」を「FEA」へ統一したのに、図のパネル見出しとボックス内に旧表現が残っていた。修正後は `grep -rn "<語>" <申請フォルダ>` と docx 抽出テキストの両方で確認し、**図は必ずレンダリングして目視する**。画像を直接編集したときは、塗りつぶしの背景色が元と一致しているかも見る（白で塗って淡色の背景を消す事故が起きた）。
