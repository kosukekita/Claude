**資格情報を発行・更新したら、「切れる前に気づく仕掛け」を必ず同時に作る。**（ユーザー指示 2026-09-03・全アプリ対象）

**Why:** 2026-08-31 に 75gravitygrab の Gmail アプリパスワードが失効し、SMTP が 8 回連続 535 で全滅した。
A/B 実験の B枠リマインド3通（8/31 20:00・9/1 08:00・9/1 20:00）が飛ばず、ユーザーは投稿の合図を
受け取れないまま 9/1 の枠を落とした。**失敗はジャーナルの奥にしか出ず、3日間誰にも届かなかった。**
真因は「通知経路＝壊れた当人」だったこと。メール障害をメールで知らせる設計は、壊れた瞬間に無言で死ぬ。

**How to apply:**
- **期限があるもの**（OAuthトークン・証明書・ドメイン・サブスク）→ 失効日をリマインダ登録し、余裕をもって事前通知。
- **期限が無いもの**（Gmail アプリパスワードは日付で切れない。親パスワード変更・2SV再設定・Google側失効で
  **予告なく死ぬ**）→ 期限リマインドは張れないので、**定期的に実際に認証を試す生存確認**を仕込む。
- 🔴**通知経路はその資格情報に依存しない独立経路にする。** 最低でも二重化
  （メール ＋ メール以外＝セッション起動時に必ず目に入るマーカー等）。
- 発行手順（Gmail アプリパスワード）: https://myaccount.google.com/apppasswords で対象アカウントにログイン →
  アプリ名（例 `gravity-smtp-2026-09`）→ 作成 → **空白を除いた16文字**を保存（再表示不可）。
  保存先は `~/.local/share/gravity/secrets/gmail_app_password`（chmod 600・末尾改行なし）。**中身は表示・ログ・コミットしない。**
- 認証テスト（送信せずに確認）: `smtplib.SMTP_SSL('smtp.gmail.com',465).login(acct, pw)` の成否だけ見る。
