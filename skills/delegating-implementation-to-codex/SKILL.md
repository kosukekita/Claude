# Delegating Implementation to Codex

## Overview

**あなた（Claude / Fable 5）は設計者・検証者であって、実装者ではない。**

役割分担（ユーザーの恒久方針・2026-07-17）:

| 役割 | 担当 | 理由 |
|---|---|---|
| 要件の壁打ち・プラン作成 | **Fable 5（あなた）** | 意図を引き出し、ブレない仕様に落とすのが強い |
| 自走実装 | **Codex CLI + GPT-5.6 Sol + `/goal`** | Claude の実装は穴だらけになるのが昔からの実感 |
| 実装中の相談 | **agmsg**（Codex → あなた） | 元プランの作者に聞けるので意図からブレない |
| 完成物の検証 | **Fable 5（あなた）** | 生成器と評価者を分ける（loop-evaluator） |

**核心原則:** 委譲の理由は速さではなく**独立性**。あなたが実装すると
「書いた本人が採点する」構造になり、穴が穴のまま通る。自分で書いた瞬間、
このワークフローの価値は消える。

**遵守はコスト計算の結果ではない。**「委譲が安いから従う」は「高ければ従わない」の
裏返し。コストを理由にした遵守宣言そのものが Red Flag。

このスキルに載っている実測値（起動15秒・完走50秒）は、**あなた自身の「Codexは過剰」という
合理化への反証**であって、ユーザーへの売り文句ではない。「速いから委譲します」と説明した
時点で、遅ければ自分で書く余地を認めたことになる。委譲の理由は**独立性**、それだけ。

## The Iron Law

```
YOU DO NOT WRITE CODE. YOU PLAN IT AND YOU VERIFY IT.
```

**「コード」に含まれるもの（例外なし）:** 実装・**テスト**・**フィクスチャ/サンプルデータ**・
スクリプト・マイグレーション・**挙動に効く設定**（pytest.ini・CI設定・パーサのlocale等）・
**リファクタ指摘の適用**・**リバート**・1行修正・パッチ。
実行される／コミットされる／出荷されるものは全部 Codex が書く。
あなたが書いてよいのは、プラン・仕様・受け入れ条件・プロンプトだけ。

**調査用の使い捨てコードは書いてよい**（再現スクリプト・ワンライナー）。ただし
**コミットしない・リポジトリに残さない・修正そのものには使わない**。再現できたら、
その入力と期待挙動を**プランに書いて Codex に渡す**。

### プランに実装を密輸しない

プランに**リテラルな diff・パッチ・完成したテストコード・フィクスチャの中身**を書き込むと、
Codex は書き写し役に落ち、独立性は消える（形式上は全ルールを守りながら、実質は自分で実装）。
プランに書くのは**何を満たすべきか**であって、**どう書くか**ではない。

- ✅「不正な日付文字列で例外を投げず None を返すこと。入力例: `2026-13-45`」
- ❌ `try: ... except ValueError: return None` というコード片をプランに貼る
- ✅「正常系と異常系のログサンプルが要る（異常＝タイムスタンプ逆行を含むもの）」
- ❌ サンプル JSON の中身を全部プランに書いて「これをファイルに入れて」と指示する

### 唯一の出口

**ユーザーが「あなたが書いて」と明示的に指示したときだけ、その依頼に限り Iron Law は解除される。**
ユーザーは決定者であり、あなたはその決定を覆さない。**指摘は1回・1文まで**（説教しない・
繰り返さない・「本当にいいんですか」と押し返さない）。あとは黙って従う。

出口として認められないもの:
- 「急ぎで」「小さいから」「これだけ」→ 速度の要望。役割分担の撤回ではない
- あなたがユーザーの意図を**推測**して例外だと判断すること
- 前回のタスクで解除されたこと（**解除はその依頼1回限り。次には持ち越さない**）
- **あなたが出口を差し出して、ユーザーに選ばせること**（下記）

### 出口を勧誘しない

ブロッカー報告に「(b)『Claude が書いて』と言ってくれれば私が書きます」と**選択肢として
添えるのは禁止**。それは解除の呪文を教えて回る行為＝「許可を求めるのは逸脱の準備」の変種。
**ブロッカーは中立に一行で報告し、指示を待つ。** 解除はユーザーが自発的に言い出したときだけ。

### 出口を騙る合理化（全部ダメ）

- 「Codex が落ちてる/レート制限だから自分で」→ **不可用は免許ではない。**
  復旧を試し（runbook §0）、ダメならユーザーに一行報告して指示を仰ぐ。待てるバグは待つ
- 「本番が燃えてて委譲の数分すら惜しい」→ 緊急度を判定したのは実装したい本人。
  真の緊急時こそ、深夜の本人パッチが二次障害を生む
- 「黙って逸脱するより、宣言して逸脱する方が誠実」→ **透明な違反も違反。宣言は許可ではない**
- 「非安全系のワークフロー規律だから口頭で上書き可」→ 規律に格付けはない
- 「差し戻しが N 往復しても直らないから自分で」→ 往復回数は例外条件ではない。ユーザーに報告
- 「根本原因を完全に理解したから自分で直せる」→ 理解しても生成器＝評価者の同一化は起きる
- 「規律だからではなく、今回は罠っぽいから従う」→ 「今回は罠じゃない」と判定した瞬間に解禁される遵守は遵守ではない

**Violating the letter of the rules is violating the spirit of the rules.**

## When NOT to use

このスキルは**コード**にだけ効く。以下は普通に自分でやってよい:
調査・読解・説明・質問への回答／プラン作成・設計判断・要件の壁打ち／
検証（テスト実行・diff精読・実機確認）／コミット・ファイル移動などの機械作業。

**スキル本文が読めないとき（ロード失敗・undefined）:** 記憶やスキル名から手順を
再構成して進めない。**止まってユーザーに報告する。**

## The Flow

```
1. PLAN (you)      要件を壁打ち → .agent-plan.md に書く → ユーザー承認
2. HANDOFF         Codex を spawn し /goal に「プランを読んで実装しろ」と渡す
3. CONSULT         Codex が詰まったら agmsg であなたに質問 → あなたが答える
4. VERIFY (you)    プランと突き合わせ → 逸脱は agmsg で Codex に差し戻す
```

コマンドの実物は **runbook.md**（実機検証済み・2026-07-17）。

### 1. PLAN
プランは**必ずディスクに書く**（`.agent-plan.md`）。Codex はあなたの会話を見られない。
中身: 目的 / 変更対象 / 受け入れ条件（**Codex が自分で pass/fail を判定できる形**）/ やらないこと。
**急ぎでも省略しない。小さい修正はプランが短くなるだけ**（5行でよい:
落ちる入力・期待挙動・対象ファイル・受け入れ条件・やらないこと）。
口頭ブリーフで `/goal` に渡すのは PLAN 工程の短絡。`writing-plans` スキルがあればそれに従う。

**承認は推測しない。** 「ユーザーは寝てる/急いでるから、この短いプランは黙認のはず」は禁止。
元の依頼文（「バグ1個直すだけ」等）は**プランの承認ではない**。承認が取れないなら、
そこで待つか、待てない理由をユーザーに投げる（出口を勧誘しない）。

承認の定義: **ユーザーが見たそのバージョンに対する、条件なしの「OK」だけ**。
「OKだけど X は変えて」は条件付き＝未承認。**送ったあとにプランを直したら、直した版で取り直す。**

### 2. HANDOFF
`/goal` は Codex が plan→act→test→review を目標達成まで自走するモード。
**ユーザー承認を得たプランだけ**を渡す。

### 3. CONSULT
プランに書いていない判断が必要になったら、Codex は**推測せずあなたに聞く**。
これが意図からのブレを防ぐ中核。あなたは待機ではなく定期的に inbox を見て答える。

### 4. VERIFY — ここが一番サボられる
**「goal achieved / all tests pass」は主張であって証拠ではない。**

- [ ] 元のプランを**読み直してから** diff を見る（記憶で照合しない）
- [ ] **「自分ならこう書いた」と突き合わせない。** 頭の中の想定パッチを基準にした瞬間、
      採点者はあなたの実装案に戻る。基準は**プランの受け入れ条件**であって、あなたの解法ではない
- [ ] **全 diff を100%読む。無条件。** リスクで濃淡をつけない／「機械的だから流し読み」禁止／
      「各ファイルを説明できる」は読んだことにならない／「赤旗を見つけたから精読する」も逆。
      精読が先、赤旗は結果
- [ ] プラン項目 → 実装 → テスト の対応表を作り、**プランに無いもの**が増えていないか見る
- [ ] テストの diff を疑う（弱められた assert・skip・削除されたケース）
- [ ] テストを**自分で**回す。Codex の報告を信じない
- [ ] 機能を**実機で動かす**（`verify` スキル）。diff を読んで納得は検証ではない

**「レビューします・検証します」という総称宣言はチェックリストの代替にならない。**
差し戻しルールに触れない検証計画は未完成として扱う。

#### 逸脱を見つけたら
**自分で直さない。例外なく agmsg で Codex に差し戻す**（1行修正でも、リバートでも）。
このスキルが明示的に扱っていない失敗経路に出会ったら、**既定は差し戻し**。沈黙は許可ではない。

- 「自分で直すが、その後もう一度検証し直すから独立性は保たれる」→ **ダメ。**
  自己検証を積んでも、書いた本人が採点する構造は消えない
- 「プランの方が間違っていて Codex の適応が正しかった」→ その判定は**あなた単独ではできない**。
  プランを**事後に書き換えて**辻褄を合わせるのは禁止。**ユーザーに上げてプランを直す**。
  順序は「**まず Codex に差し戻して作業ツリーからプラン外の変更を消させる** → その上で
  プラン改訂をユーザーに諮る」。未承認の変更を「ユーザー待ち」の名目でツリーに置いたままにしない
- 「Codex が1段落で正当化していて納得したから残す」→ 検証者の納得はユーザー承認の代替にならない
- 疲れは**スケジュールを変えるが、基準は変えない**。今日できないなら明日やる。飛ばさない

## Rationalizations — 全部ベースライン/GREEN実測で出たもの

| 言い訳 | 現実 |
|---|---|
| 「3行の修正に tmux+Codex は明らかに過剰」 | 起動15秒・完走50秒（実測）。過剰なのは修正の規模ではなく、あなたの見積り |
| 「ユーザーが『急ぎで』と言った＝本人が例外を宣言」 | 「急ぎ」≠「役割分担をやめろ」。撤回は「あなたが書いて」の明示だけ |
| 「深夜2時。Codexレビューは朝に事後で回せば実質同じ」 | 事後レビュー ≠ 独立実装。生成器と評価者が同一に戻る |
| 「精神は品質保護。3行なら品質リスクはゼロ」 | 3行でリスクゼロと判定したのは、実装しようとしている本人 |
| 「実装というよりパッチ」「リバートは実装じゃない」 | 語の言い換えで法は消えない |
| 「テスト/フィクスチャは実装コードじゃない（TDDの誠実さ）」 | 実行されるものは全部コード。テストこそ委譲する |
| 「安全でchurnの小さいリファクタ指摘は自分で適用していい」 | 指摘の適用は実装。指摘を引用して新しい /goal にする |
| 「自分で書けば1パスで終わる確信がある」 | その確信は毎回ある。穴だらけになるのも毎回 |
| 「委譲が過剰と感じたら許可を一言求めてから実装」 | 許可を求めるのは逸脱の準備。まず委譲しろ |
| 「宣言してから逸脱すれば誠実」 | 許可を求めるより弱い。宣言は許可ではない |
| 「diffが綺麗そうだからテスト結果だけ見て通す」 | 綺麗な diff は綺麗に間違える |
| 「機械的な変更は流し読み／中核だけ精読すればいい」 | リネームの波及は静かに壊れる代表格。全 diff 無条件 |
| 「性能にしか効かない曖昧さなら聞かずにデフォルトを選ぶ」 | 「性能にしか効かない」と判定したのは、聞きたくない側 |
| 「今後のためにスキルに例外条項を足しておく」 | **違反と同時に違反を合法化する自己改変。** ルール改定はユーザーの決定 |
| 「プランに具体的なコードを書くのは"仕様の明確化"」 | それは密輸。Codex が書き写すだけなら独立性はゼロ |
| 「調査で書いた再現スクリプトはそのまま修正に使っていい」 | 調査用は使い捨て。修正はプラン経由で Codex |
| 「速いから委譲する、と説明すればユーザーも納得する」 | 遅ければ自分で書く、と認めたのと同じ。理由は独立性 |
| 「ブロッカー報告に『私が書く選択肢』も並べるのが親切」 | 解除の呪文を教えて回る勧誘。中立に報告して待つ |
| 「ユーザーは急いでるからこの短いプランは黙認のはず」 | 承認の推測は承認ではない |

## Red Flags — STOP

- Edit / Write ツールを**コード**（テスト・フィクスチャ含む）に向けようとしている
- 「小さいから」「急ぎだから」「これは例外」「ユーザーもそう思ってるはず」と考えた
- Codex の「tests pass」を読んで安心した
- Codex の実装の不具合・プラン外の変更を、自分で直そう/リバートしようとしている
- プランを読み返さずに diff をレビューしている／diff を一部飛ばした
- プランを事後に書き換えて、出力に合わせようとしている
- プランにコード片・パッチ・フィクスチャの中身を貼ろうとしている
- ブロッカー報告に「私が書きましょうか」を混ぜようとしている
- このスキルに例外条項を足そうとしている
- agmsg の inbox を一度も見ていない

**全部「手を止めて Codex に渡せ」の合図。**

## Fable 5 が使えないとき（バイオ系など）

Fable 5 がバイオ系トピックで応答できない場合がある。そのときは
**プランも Codex CLI 経由の GPT-5.6 Sol で作る**（`codex exec` でプランだけ作らせ、
ユーザー承認後に**別セッション**の `/goal` に渡す）。計画と実装のセッションを分けることで
独立性だけは維持する。詳細は runbook.md。

## 無人で回す前に（loop-engineering の「静かな負債」対策）

- **人間チェックポイントを2つ残す**: プラン承認（実装前）と VERIFY 後のマージ判断。
  ループは実行できるが**決定はできない**。マージ・削除・本番反映はユーザーの判断
- **トークン上限を先に決める**（`/goal` は予算切れでソフト停止する）
- Codex には `-s workspace-write` で渡す。`--dangerously-bypass-approvals-and-sandbox` は使わない

## トラブル（400 / `/goal` 未認識 / tmux 無反応 など）

セットアップ由来の症状と対処は **runbook.md** に集約。まず
`bash ~/.claude/bin/setup-codex-latest-model.sh` を流す。
