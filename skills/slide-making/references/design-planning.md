# Design Planning — slide-making

**スライドをいきなり作らない。** まず Markdown で「設計図」を起こし、AskUserQuestion で構成・構造・グラフ形式を
合意してから HTML/PPTX 実装に入る。本書はその設計図フェーズ（SKILL.md「STEP 1 — 設計図」）の中身。

> このフェーズで決めるのは**何を・どの順で・どの型で・どの図で**見せるか。
> **見た目（配色・余白・強調・脱文章ルール）は決めない** — それは既存の「コンテンツ設計」節と `design-rules.md` が正。
> 本書はそれらを**再掲しない**。重複箇所はリンクで既存を参照する。

## 0. 設計図フェーズの位置づけと対話設計

`STEP 0（HTML/PPTX 確認）` → **本フェーズ** → `コンテンツ設計` → `パス A/B 実装`。

**AskUserQuestion は「束ねて最小往復」で投げる。** 1枚ずつ質問を連打しない。既定の対話ラウンドは次の3〜4回:

| ラウンド | 何を聞く | 形式 |
|---------|---------|------|
| R0 | 出力形式（HTML/PPTX）＋**ブリーフ7項目ゲート**（テーマ・目的・対象者・枚数・時間・観客の変化・媒体、`creative-direction.md §1`）＋数字スライドがあるなら手元の数字。選択式は**束ねて**、自由記述はテキストで | AskUserQuestion＋テキスト |
| R1 | **中心概念**（フェーズ2）＋デッキ全体の構成（9部の物語構造ベース。各スライドのタイトル候補・順序・枚数）を Markdown 見出しリストで提示し合意 | AskUserQuestion |
| R2 | **3方向デザイン案の選択**（フェーズ5）＋**各スライドの構造型と図種**をまとめて提示（1枚1問ではなく一覧で）。迷うスライドだけ選択肢化 | AskUserQuestion |
| R3 | **反対監査の結果**（フェーズ6・4段階判定）と修正済みの全設計図（後述スキーマ）を提示し最終承認 | AskUserQuestion |

- 枚数が多いデッキ（〜10枚超）は **1枚ずつ往復しない**。R1 で全体を合意 → R2/R3 で**まとめて**提示する。
- 「丁寧に1枚ずつ詰めたい」とユーザーが明示したときだけ、各スライドを逐次 AskUserQuestion にする。
- **承認前に HTML/PPTX 実装を始めない**（最頻の事故）。

## 1. 入力ゲート（着手前の必須確認 — ブリーフ7項目＋数字）

設計図に着手する前のゲートは**ブリーフ7項目**（テーマ・目的・対象者・想定枚数・発表時間・観客の変化・利用媒体）。
正本は `creative-direction.md §1` — **未指定項目は先に質問して埋める**（揃うまで設計図を書かない）。
旧・入力3点はブリーフに次のとおり吸収される:

1. **読み手は誰か** → ブリーフ #3 対象者
2. **一番言いたいこと** → ブリーフ #6 観客の変化の「終了後」（**開始前**の認識・不安・誤解の定義が追加で必須）
3. **手元の数字** — 図の根拠になる実データ。ブリーフ外だが数字スライドを作るなら従来どおり必須

**読み手で粒度・語彙を切り替える:**

| 読み手 | 見せ方 |
|--------|--------|
| 経営層 | 結論と効果を先に。数字は要点のみ。判断に効く差分だけ |
| 実務者 | 手順と根拠を厚く。プロセス・前提・例外を残す |

## 2. Markdown 設計図のスキーマ（このフェーズの成果物）

設計図は**1スライド = 1 Markdown ブロック**。以下のフィールドを必ず埋める。これが R3 のレビュー単位。

```markdown
## S03  ← スライド番号
# {言い切りタイトル｜体言止め・断定・15字以内}
> GOAL: {相手に何を理解させ・何をしてほしいか（1文）}
- 構造型: {順番｜対比｜仕分け｜問題打ち手効果｜因果｜結論先出し} の1つだけ
- 軸: {並べる軸を最大2本。例「時間 × 部門」}
- 図種: {下の選定表から1つ。数字スライドのみ}／数字の種類: {生値｜割合｜前年比} を1つ固定
- 配置: 事実=見出し / 根拠=図 / 解釈=欄外（→ だから…）
- テンプレ: {assets/template.html の T-NN ＋ slide-templates.md の §N}
→ だから(So What): {聞き手の行動・意味に接続する1行}
```

**書けない＝作らないの原則:**
- `GOAL` が書けないスライドは作らない。
- `→ だから(So What)` が書けない見出しは弱い。作り直す。
- タイトルが説明ラベル（`〜について`/`〜の検討`/`〜の現状`/`〜とは`）になっていたら言い切りに直す。

## 3. 主張を決める（設計図の核）

1. **読後ゴールを1文で先に書く。** 作図はその後。ゴール＝相手に何を理解させ何をしてほしいか。
2. **主張を先に決めてからグラフを選ぶ（逆算順序）。** 「データから何が言えるか」ではなく
   「この主張を裏づけるにはどの数字・どの図が要るか」の順。**グラフは主張の証拠であって主役でない。**
3. **数字の種類を1枚で固定する。** 生値（絶対量）/ 割合（構成・シェア）/ 前年比（変化）のどれで語るかを
   主張に合わせて**1つ選び、1スライド内で混ぜない**。（数値そのものの改変禁止は既存「コンテンツ設計 #5」が正）
4. **5つの切り口で軸を探す。** 種類・時間・場所・順番・大小 の5観点を当てて並べ軸を見つけ、
   **主張に効く軸を最大2本**に絞る。3本目はスモールマルチプル（分割）か別スライドへ。
5. **本文の骨格は「結論＋根拠（最大3点）」。** ただし**共通ルール#2「テキスト最大3行」が上限の正**。
   結論1行＋根拠は3行に収まる範囲で（＝結論1＋根拠最大2が目安、図に根拠を逃がせるなら本文は結論1行のみ）。
   根拠が多いときは削るか別スライドへ。
6. **つかみは口頭で台本化（スライド本文ではない）。** 状況→引っかかり→問い→このスライドの答え、の順で
   話者の流れを作る。スピーカーノート側に書き、スライド面には載せない（共通ルール「描かないもの」）。

## 4. 構造6型 — 選定表（1スライド1型）

「伝えたいこと」から型を**1つだけ**当てる。**1枚に構造型は1つ・詰める軸は2つまで**。
2つ言いたければ2枚に割る（最頻のつまずき）。テンプレは `assets/template.html` の **T-NN**（完成例）と
`slide-templates.md` の **§N**（コピー用スニペット）の二段で参照する。

| 型 | こう書けたら使う | レイアウト | テンプレ |
|----|----------------|-----------|---------|
| **順番（フロー）** | 工程・手順・時系列・段階（まず/次に/STEP/年月） | 左→右の矢印フロー。各段を等大カードで等間隔、3〜5段（参照テンプレ T-03/§7 は4段ベース。3/5段は段数を増減して使う） | T-03 ステップ / T-11 ロードマップ / §7 |
| **対比（左右2列）** | 現状vs理想 / A案vsB案 / Before vs After | 左右2列を**同じ観点軸・同じ粒度**で。中央は border-right の縦線で仕切る（表は使わない）。Before/After は旧状態を破線で | T-07 対比比較 / §4 |
| **仕分け（MECE）** | 分類・カテゴリ整理・網羅。漏れなくダブりなく | 階層分解→ツリー、2観点の掛け合わせ→マトリクス（横線のみの表） | T-05 要素分解 / T-09・T-10 比較表 / §5 |
| **問題→打ち手→効果** | 課題があり・こう打ち・こう効く（提案/施策） | 3ブロックを左→右（問題/打ち手/効果）。各ブロック見出し＋根拠1〜2行、打ち手→効果を矢印で接続 | **既存テンプレ無し → §「未整備2型のスニペット」参照** |
| **原因と結果（因果）** | なぜそうなるか / これをやるとこうなる（因果1本） | 左パネル（原因/なぜ）→矢印1本→右パネル（結果/だから）。矢印は1本に絞る | T-08 因果図 |
| **結論先出し（三角形）** | 結論とその根拠。まず結論を印象づけたい（主張スライドの既定） | 上に結論1行（大）、下に根拠3つを横並びの逆三角構図 | T-01 グラフ強調の右結論 / §8 まとめ（**逆三角専用は半新規 → 下記スニペット**） |

### 未整備2型のスニペット（HTMLパス）

既存テンプレに無い「問題→打ち手→効果」「結論先出し（逆三角）」は、既存の `assets/slide-base.html` の CSS 変数を使い、
次の骨格で組む（縦罫線禁止・border-right で仕切る・色は Iron Law に従う）。

```html
<!-- 問題→打ち手→効果（3ブロック） -->
<div class="row" style="flex:1; align-items:stretch; gap:0; margin-top:1em;">
  <div class="col" style="flex:1; padding:0 32px; border-right:2px solid var(--text-color);">
    <h2 class="slide-heading">問題</h2><p class="slide-body">{{...}}</p>
  </div>
  <div class="col" style="flex:1; padding:0 32px; border-right:2px solid var(--text-color);">
    <h2 class="slide-heading">打ち手</h2><p class="slide-body">{{...}}</p>
  </div>
  <div class="col" style="flex:1; padding:0 32px;">
    <h2 class="slide-heading"><span class="emp-u">効果</span></h2><p class="slide-body">{{...}}</p>
  </div>
</div>
```

```html
<!-- 結論先出し（逆三角: 上に結論1行・下に根拠3つ） -->
<div class="center" style="margin-top:0.6em;">
  <h1 class="slide-title" style="text-align:center;"><span class="emp-u">{{結論1行}}</span></h1>
</div>
<div class="row" style="margin-top:1.2em; gap:48px; align-items:flex-start;">
  <div class="col center" style="flex:1;"><p class="slide-body">① {{根拠1}}</p></div>
  <div class="col center" style="flex:1;"><p class="slide-body">② {{根拠2}}</p></div>
  <div class="col center" style="flex:1;"><p class="slide-body">③ {{根拠3}}</p></div>
</div>
```

PPTX パスでは同じ意図を `cards`（3カラム）＋ タイトルで組む（`pptx-guide.md` の cards スキーマ）。

## 5. グラフ12選 — 選定表 ＋ 実装可能性

主張に効く図種を選ぶ。**色の強調本数・3D禁止・メイン/アクセント配分は既存 Iron Law（SKILL.md）と `design-rules.md §4` が正**
（本書では再掲しない）。ここに書くのは**選定条件・項目数しきい値・代替先・実装手段**だけ。

### 実装可能性（最重要 — 設計図で選ぶ前に確認）

| 描画手段 | 直接描ける図種 |
|---------|--------------|
| **HTMLパス（Chart.js 4 標準）** | 棒・横棒・折れ線・円/ドーナツ・散布・バブル・積み上げ棒/面・レーダー |
| **HTMLパス（要プラグイン or 自前作図）** | ヒートマップ（matrix プラグイン）・サンキー（sankey プラグイン） |
| **どちらのパスでも標準では描けない** | ファネル・モザイク/面積図・ベン図・サンキー・ヒートマップ |
| **PPTXパス（`build_pptx.py`）** | **ネイティブグラフ非対応**（table/cards/images のみ） |

→ **Chart.js 標準外の図（ファネル・サンキー・ヒートマップ・モザイク・ベン）と、PPTX の全グラフは
`parts/*.png` として画像化**（GPT Image でパーツ生成 → 埋め込み）するのが既定。設計図の「図種」欄に
**`（実装: Chart.js / 画像parts）`** を併記して、実装手段まで合意しておく。

### 選定表

| 図種 | 使うとき | しきい値・ルール・代替先 | 実装 |
|------|---------|------------------------|------|
| **棒** | カテゴリ間の差・大小（順番なし） | 10項目以内。3D禁止。横棒なら長名可。3以下のファネルもここ | Chart.js |
| **折れ線** | 時系列の推移・トレンド | 線4本まで。転換点に注釈1つ。順番のないカテゴリには使わない（→棒） | Chart.js / §6 |
| **円** | 割合で、かつ1要素が過半に偏るのを見せたい**ときだけ** | 5項目以下 **かつ** 過半に注目。それ以外の割合比較は**棒** | Chart.js |
| **ファネル** | 段階ごとの歩留まり・転換率 | 4〜6段。各段に残数/転換率。3以下→棒、7以上→表 | 画像parts |
| **バブル** | 3軸（X・Y・大きさ）同時 | 大きさ＝**面積**で量（半径でない）。注目バブルだけ着色 | Chart.js |
| **ヒートマップ** | マトリクスの濃淡・密度パターン | 単色グラデ1スケール。行・列ラベル必須 | プラグイン / 画像parts |
| **面積図（モザイク）** | 2つの量の掛け算（単価×数量 等） | 縦×横＝量の積。「面積＝価値」を見出しで明言 | 画像parts |
| **散布図** | 2変数の関係・相関 | 事実は見出し・解釈は図の下。点が多ければ回帰線/クラスタ | Chart.js |
| **ベン図** | 集合の重なり・共通部分 | 円2〜3個。重なりに意味を明記。4集合以上→表 | 画像parts |
| **積み上げ面** | 総量とその内訳の推移 | 系列を主要内訳に絞る。実績/見込みは下記で区別 | Chart.js |
| **サンキー（流れ図）** | 量の流れ・配分 | 帯の太さ＝量。流入と流出の総量を一致させる | プラグイン / 画像parts |

### 全グラフ共通 — 実績/見込みの区別

実績と予測が混在するときは、**実績＝濃い実線・塗り / 見込み＝薄い色・破線**で必ず分け、
境界に縦の区切り線か「ここから予測」注釈を入れる。（`slide-templates.md §6` の破線は参考系列用途のみなので注意）

## 6. 言葉 — 見出しの言い切り（設計図段階で詰める）

「脱文章・ラベルは単語か数字のみ」という大方針は**既存「コンテンツ設計 #2」が正**（再掲しない）。
ここは見出し**文言**の具体ルールだけ。

- **言い切る**: 体言止め＋断定。`〜について`/`〜の件`/`〜とは`/`〜の検討`/`〜の現状` は禁止。
  NG「売上の推移について」→ OK「売上は3年で2倍」。
- **15字以内**: 超えたら情報を本文・図へ逃がす。
- **結論を先出し**: 見出しを読むだけで主張が伝わる。
- **数字で具体化**: 「大幅に増加」→「42%増」、「多くの」→「3社中2社」。
- **受け身を能動に**: 「改善が見られた」→「改善した」。
- **ぼかし言葉を削除**: `など`/`等`/`かもしれない`/`と思われる`/`基本的に`。断定できないなら根拠を足すか主張を変える。
- **言い切り案を10個出して最良1つを選ぶ**（主張スライドの見出し）。
- **同じ語を二度書かない**: 複数項目に共通する語は軸ラベル/見出しに1回だけ出し、各項目から省く。
  （略語の初出フルスペルは `design-rules.md §6` が正）

## 7. 配置原則（事実/根拠/解釈の物理分離）

- **事実＝見出し / 根拠＝図・表 / 解釈＝図の外（欄外・別枠）。** 図の中に「だから〜」を書き込まない。
- **注釈・出典は欄外（小さめ）に置き、本文に混ぜない**（出典の配置例は T-04）。
- **矢印は1つの相手にだけ向ける**（複数を指さない）。
- スライドの**主役（最初に視線を置く1点）を1つ決める**。色での強調は最後・Iron Law の範囲内（`design-rules.md §4`）。

## 8. 設計図フェーズのつまずき（チェックリスト）

R3 の最終レビューで確認する。**設計図フェーズ固有の項目だけ**（強調・色・1メッセージの最終確認は既存「よくある失敗」表に委ねる）。

- [ ] ブリーフ7項目（テーマ・目的・対象者・枚数・時間・観客の変化・媒体）＋数字が揃っているか。未指定を聞かずに着手していないか
- [ ] 中心概念（フェーズ2）を R1 で合意し、3方向デザイン案（フェーズ5）を提示・選択したか
- [ ] 反対監査（フェーズ6）を R3 の直前に実施し、修正済み構成を提示しているか
- [ ] 9部の物語構造からの統合・省略を明記して合意したか（黙って捨てていないか）
- [ ] 各スライドに `GOAL` と `→ だから(So What)` が書けているか
- [ ] タイトルが言い切り（体言止め・15字以内・説明ラベルでない）か
- [ ] 1枚の構造型は1つ・軸は2つまでか（2つ言いたい→2枚に分割したか）
- [ ] グラフは主張から逆算で選んだか（先にグラフを決めて主張を後付けしていないか）
- [ ] 数字の種類（生値/割合/前年比）を1枚で固定したか
- [ ] 選んだ図種が出力パスで**実装可能**か（Chart.js 標準外/PPTX グラフは画像parts に回したか）
- [ ] 設計図をユーザー承認済みか（**承認前に HTML/PPTX 実装を始めていないか**）
