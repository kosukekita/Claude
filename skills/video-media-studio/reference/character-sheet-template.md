## ★固定ルール（参照あり経路 = (B)(C) に適用・ユーザー確定 2026-07-07）

以下の2点は**参照画像を使う経路（(B) NSFW 派生・(C) 既存画像からのシート化）**のすべてのリファレンスシートに機械的に適用する（ユーザー確定・以後確認不要）:

1. **シートに文字・ラベルを一切入れない。** タイトル・パネル名・日本語ラベル・英語ラベルすべて禁止。純粋に画像パネルだけで構成する（罫線・ボックスによる区画整理は可）。汎用テンプレートの「短い日本語ラベルのみ入れる」指示はこのルールで**上書き**され無効。
   - **Why**: ラベルは資料としての用途（v2v `--face-ref` / i2v `--image` の素材切り出し元）に不要で、文字化けや英語混入の事故源にもなる。パネルの意味はレイアウト位置（左＝全身3面、右＝顔・表情等）で自明。参照あり経路のバックエンド（Qwen-Image-Edit / FLUX.2-dev / Grok）は画中日本語テキストが特に弱い。
2. **元画像（参照シート）から顔アップや表情パネルをクロップして流用しない。全パネルを生成で作る。** 顔アップ・横顔・斜め・表情差分も、参照を条件にした生成（Qwen-Image-Edit / FLUX.2-dev editing / FLUX.1 Kontext / Codex `-i`）で新規に描き起こす。
   - **Why**: 参照シートのアップを切り貼りすると、①元の着衣（襟等）が写り込む ②全身生成パネルと画質・ライティングが不整合 ③そのビュー（斜め45度・特定表情）が元シートに無ければ埋められない。全パネルを同一設定で生成すれば統一感が出て、シート全体が「同一人物の生成物」として一貫する。

> この2ルールは (B)(C) の他の記述より優先する。汎用テンプレート内の「日本語ラベルのみ入れる」等の文言と矛盾する場合は本節が勝つ。
>
> **適用範囲（2026-07-09 ユーザー確定）**: 本節は**参照なし t2i の (A) には適用しない**。(A) は Codex(GPT Image) が画中日本語を正確に組めるため、日本語短ラベル入りで生成する（稼働中の `daily_sfw_sheet.mjs` も同じ）。上のルール1の Why（文字化け・切り出し元としての不要さ）は参照あり経路の事情であり、(A) の運用実績とは競合しない。

## (A) ペルソナ新規 SFW シート（参照なし・t2i）

**「新しいSFWのキャラシートを作って」と言われたらこれ。参照画像を求めない。★固定ルールは (A) には適用しない（日本語短ラベルを入れる）。**

- **ペルソナ固定ルール（2026-07-08 ユーザー確定）**: ①年齢 = 25〜35 歳の間 ②顔 = 100 点満点中 **75 点**（完璧すぎない自然で親しみやすい可愛さ。アイドル級の美形にしない）③胸 = **G カップ（とても胸が大きい）**。
- **残りの特徴（髪型・髪色・職業・婚姻・服装・雰囲気）は自動設定してよい**（ユーザー確認不要 = 人物 6 要素確認フローの明示的例外。ユーザー確定済み）。職業・年齢は偏りやすいので乱数カテゴリで強制的に散らす。
- **★胸の視認性ルール（2026-07-08 実機比較でユーザー確定）**: ①胸は**画像プロンプト3箇所で反復**（ペルソナ行「Gカップで、とても胸が大きい…一目で分かる」＋最重要条件「体型（大きな胸を含む）」＋服装節「体のラインが出るシルエットで…はっきり分かる」）②**ペルソナの細部（顔立ちの長文・スリーサイズ・雰囲気・職業）は画像プロンプトに入れない**＝胸情報の希釈を防ぐ（記録は persona.json/md 側に残す）③服装は**ペルソナの職業・性格が伝わる私服＋体のラインが出るトップス**。無難な白シャツ＋ネイビーパンツは避ける ④体型記述に「スリム」「華奢」を使わない（胸指定と相殺する）。
- 絵柄は**実写調（フォトリアル）が既定**。
- **バックエンド**: 第一選択 = Codex(GPT Image) text-only（`-i` なし）。**カップ指定は Codex が `sexualized content` で拒否することがある** → 拒否時は「とてもグラマラスで胸元にボリュームのある体型」の婉曲表現で再試行、なお拒否なら **Grok CLI（日本語のまま・翻訳禁止）**へ。Grok は生成可能だがラベル文字化け・見出し誤りが出やすい（2026-07-08 実測）＝保険扱い。
- **★構成（2026-07-09 ユーザー確定・方針A = 参照専用ミニシート）**: フルシート（多パネル）はやめ、**r2v/i2v への供給に最適化した4パネルだけ**にする — **【全身】正面／【バストアップ】正面／【バストアップ】斜め45度／【顔アップ】正面**。狙いは2つ: (1) **1回の生成に少数パネルを収めて全パネルの同一人物性を担保**（別々に生成すると GPT Image は seed 固定できず別人化する）(2) **各パネルを大きくする**＝r2v の参照画像は最低 **240×240** 必要なので、フルシートの極小タイル（実測 160×280）だと拡大が要る問題を発生源で解消。表情・顔パーツ・髪詳細・別角度・後ろ姿は「参照として動画に渡す」用途に不要なので落とす（全角度の記録が要るときだけ別途フル構成を回す）。実際に r2v へ渡すのは 2〜3 枚（全身＋顔が identity の核、バストアップは補強）。
- **全身正面のポーズ指定**（2026-07-09 実測）: 全身正面は体型の参照なので、**手は体の横に下ろし、胸や体のラインを手で隠さない**立ち姿にする（腹の前で手を組むと G カップが分からず体型参照としても弱い）。胸の視認性はバストアップ正面＋斜め45度が主に担保する。
- 検証: 全パネルの同一人物性・**胸の大きさが服の上から分かるか**・日本語ラベルの文字化け・破綻を目視 → 合格したら**この SFW シートをマスターリファレンスとして保存**（`~/media-out` 推奨。image-cache は揮発）。
- **毎朝 9:00 JST の無人生成**は `~/media-out/sheet-factory/daily_sfw_sheet.mjs`（systemd --user `sheet-factory.timer`）が本テンプレートのヘッドレス実装として稼働中（pCloud `Data/NSFW/AIgenaratedSheet/` 保存＋Gmail 通知）。文言を変えるときはスクリプトと本ファイルを両方更新する。

## (B) SFW シート → NSFW シート派生（参照 = 完成 SFW シート）

**「このSFWシートからNSFWシートを作って」と言われたらこれ。** 参照画像 = (A) で作ったシート（または本人確認済みの同一キャラ画像）。★固定ルール（文字なし・クロップ流用禁止）を適用する。

- **経路はローカルのみ**（Codex/Grok は NSFW 参照・NSFW 出力とも拒否。**NSFW（nude 等）はこの経路一択**＝実証 2026-07-07）:
  - **Qwen-Image-Edit**: `gen_qwen_edit.py --image sheet_sfw.png`。cu121 ピン等は SKILL.md / 記憶の既存知見どおり。
  - **FLUX.2-dev editing**: `gen_flux2_edit.py --image ref.png [--image ref2 ...]`（`Flux2Pipeline` に `image=[PIL,...]` を渡す＝単一/マルチ最大 10 枚の参照編集。4bit 量子化で 48GB に収まる）。Qwen-Edit と使い分けて画質を比較する用途。
- **パネルは一枚絵に詰め込むより、各ビューを個別クロップ → 各々を参照条件で生成 → PIL でグリッド合成が確実**（複数人物パネルを一度に整合させる制御が難しいため）。合成コードにタイトル・ラベルの描画を入れない（★固定ルール1）。
- **汎用テンプレート（下記）を次の 3 点だけ改変して使う**（この改変はユーザー確定済みの定型なので事前確認不要。ただし NSFW 衣装の具体が依頼に無い場合はそこだけ確認）:
  1. **服装節を差し替え**: 「過度な露出、下着、水着、性的な衣装は避けてください。」の行を削除し、依頼された NSFW 衣装/露出指定に置き換える（例:「下着姿で統一」「上半身裸」等、**内容はユーザーの依頼から取る**）。
  2. **ネガティブ指定から「性的な衣装、下着、水着」を削除**（残りのネガティブは全部維持。これを消し忘れると NSFW 指定を自分で打ち消す）。
  3. **ローカル NSFW 構成調整を適用**（補足ルール参照: 【表情】行を丸ごと削除・【顔アップ】【顔パーツ】は必ず残す・【全身】は各向き 1 枚・【髪の詳細】【別角度】維持）。
- 検証: **SFW シートの顔と NSFW シートの全パネルを目視比較**（同一人物性が本パイプラインの生命線）＋**文字が入っていないか**。複数パネル一枚絵の品質は未実測につき**初回はまず 1 枚出して確認**してから本番。
- 完全ローカル処理・外部送信しない。

## (C) 既存画像からのシート化（参照 = 任意の人物/キャラ画像）

既存の実写人物・イラスト・アニメ・漫画・3D・デフォルメキャラの画像 1 枚からシートを起こす従来フロー。★固定ルール（文字なし・クロップ流用禁止）を適用する。

1. **参照画像の正立確認**: スマホ縦長写真は EXIF で 90° 横倒しのことがある。`ffmpeg -noautorotate -i src.jpg -vf transpose=2 -map_metadata -1 up.jpg` で正立を確認してから使う。
2. **絵柄判定を先にやる**: 参照画像を Read で見て「実写 / アニメ / 漫画 / 3D / デフォルメ」を判定（検証時に「勝手に実写化/アニメ化されていないか」を見る基準）。
3. **バックエンド**: 第一選択 = Codex(GPT Image) `codex exec --skip-git-repo-check --sandbox workspace-write -i ref.png < prompt.txt`（`-i` 添付＋stdin。位置引数併用不可）。出力は `~/.codex/generated_images/<sid>/ig_*.png` から回収。拒否時 = Qwen-Image-Edit（`gen_qwen_edit.py --image ref.png`・初回 1 枚テスト）または FLUX.2-dev editing（`gen_flux2_edit.py --image ref.png`）。`gen_image.py` ローカル系（参照非対応）と Grok（image_edit ヘッドレス不発火）は不可。
   - ⚠ **FLUX.2 [pro]/[flex] はオープンウェイトではなく API（Replicate/fal/BFL）専用**。ローカルで動くオープンウェイトは **FLUX.2-dev / FLUX.2-klein**（HF にあり）。FLUX**.1** 系で参照編集は **FLUX.1 Kontext**（`gen_kontext.py`）。※以前スキルの `gen_image.py` が flux.2-dev を t2i のみ実装していたのは image 引数を渡していなかっただけ（診断済み 2026-07-07）。
4. 下の**汎用テンプレートを原文のまま**使う（自己完結なので 6 要素確認フローは適用しない。パネル削減・比率変更などの改変だけ事前確認）。★固定ルールは上書き不可で常に適用。
5. **検証**: ①各パネルが元画像と同一人物/キャラか ②絵柄維持 ③**文字が入っていないか**（★固定ルール1違反＝文字/ラベルがあれば再生成）④パネル欠け・顔の重複・手指の破綻。崩れたら再生成。

## 補足ルール

- **★ローカルモデル（Qwen-Image-Edit 等）で NSFW シートを作るときの構成調整（2026-07-07 ユーザー確定）**: ローカルモデルは Codex(GPT Image) と違い、**小さいパネルを1つ1つ精密に描く解像度・能力が無い**（小さい顔タイルの羅列は崩れる／同一性が落ちる）。そこでローカル経路の NSFW シートは次のように「入れる内容」を調整して生成する（ユーザー確定済みなので事前確認は不要）:
  - **【表情】の行（通常・笑顔・…困り顔の8連）は丸ごと削除**する。← 小さい顔タイルが最も崩れる。
  - **【顔アップ】（正面・横顔・斜め45度）と【顔パーツ】（目・眉・鼻・口・耳・輪郭・肌・質感）は残す**。← 表情とは別物、同一性の核なので必ず入れる。
  - **【全身】は正面・背中を何枚も並べず、各1枚程度に絞る**（正面1・横1・後ろ1 で十分。同じ向きの全身を量産しない）。
  - 【髪の詳細】【別角度】も残す。
  - Codex 経路（SFW シート等）はフル構成でよい＝この調整は「ローカル×NSFW」の組み合わせに限る。
  - なお (A) の SFW テンプレートは 2026-07-09 に【表情】を 3 種へ削減済みなので、この「表情行を丸ごと削除」は (A) 由来のプロンプトを (B) に流用するときにだけ効く。
- **入れ墨の固定ルールとの整合**: (A) ペルソナ新規はテンプレートのネガティブに入れ墨禁止を織り込み済み。(B)(C) は元画像に入れ墨が**無い**場合のみネガティブ指定の末尾に「入れ墨・タトゥーの追加、肌への文字や模様の追加」を足し、**ある**場合は同一性優先でそのまま再現する（勝手に消さない）。
- **16:9 の近似**: GPT Image の出力サイズは固定刻み（横長は 1536×1024 ≈ 3:2）。テンプレートの「16:9 横長」はレイアウト指示として機能するが、厳密な 16:9 が必要なら生成後に ffmpeg の pad/crop（`reference/ffmpeg-recipes.md` の resize-crop-pad）で調整する。
- **自然化プロンプトとの関係**: 実写調シートで「AIっぽさを消したい」要望が付いたら `reference/realism-naturalization-prompts.md` から提案してよい。ただしシートは資料であり SNS 写真ではないので、レイアウト指示と矛盾する項目（生活感のある背景等）は入れない。
- **パネル一部だけ欲しい場合**（表情集だけ・三面図だけ等）: 「入れる内容」を該当ブロックだけに削って使う（削減はユーザー確認済みの場合のみ。レイアウト・最重要条件・ネガティブはそのまま残す。(A) はラベルも残す）。
