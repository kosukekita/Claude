# Key Visual Director — video-media-studio

**広告・Web・スライド用キービジュアル生成の既定フローの正本。** ユーザー指定プロンプト（§2・2026-07-21 確定）を
キービジュアル制作の**既定フロー**として実行する。§2 の全文は**改変禁止**。
**§1・§3 は §2 と同格の必須規範であり、§2 の実行条件を定める（§2 単独では着手できない）。**
「正本に無い工程だから省略可」という読みは §4 の合理化に該当する。

> **※ §2 は受領時点の全文（2026-07-21）。末尾の「プロ級監査ブロック」は見出しのみで本文未受領** —
> 本文が届くまで **§3 K2 の監査仕様（暫定）** が代替する。届き次第 §2 に追補し §3 を差し替える。

**適用範囲**: 広告・Web・スライド・SNS サムネイル等に使う**非人物のキービジュアル（SFW）**の生成
（用途例: Xサムネイル / LPファーストビュー / スライド表紙 / Web背景）。
**リアル人物が主役として登場する画像・動画・NSFW は対象外** — 従来フロー（人物6要素・★1本ルール・動画3ゲート）が優先する
（正本の【避ける表現】も「用途と無関係な人物」を禁じている）。
slide-making / ui-ux-design（LP・サイト）のフローからキービジュアルが必要になった場合も本フローで生成する。

**★1本ルールとの関係（2026-07-21 ユーザー確定）**: 「★生成は一度に1本だけ」は**リアル人物画像・動画生成の規律**であり、
Web/スライド用キービジュアルには**適用しない**（明確に分離）。本フローの既定は **3案（A/B/C 各1枚）＋改善版1枚＝計4枚**。
ただし seed 違いの並列量産はせず、**1枚ずつ順次生成し、各生成後に軽検品**（文字混入・破綻）してから次を生成する
（プロンプト欠陥を量産しないという1本ルールの精神は維持）。計4枚を超える生成はユーザーが本数を明示した時のみ。

## §1 ブリーフ2項目ゲート（必須質問）＋ディレクター設計項目

§2 の `{{ }}` のうち、**ユーザーに必ず質問するのは次の2項目だけ**（2026-07-21 ユーザー確定）。
未指定なら着手前に質問する。「任せる」「業界的に自明」「急ぎ」は省略理由にならない。

| # | 項目 | 充足の判定 | 聞き方 |
|---|------|-----------|--------|
| 1 | 用途 | 依頼文から**一意に**読み取れれば充足（K0 で1行明示して認識合わせ）。読み取れなければ質問 | AskUserQuestion（Xサムネイル/LPファーストビュー/スライド表紙/Web背景＋Other ※1問の選択肢は4つまで） |
| 2 | 伝えたい概念 | 明示がなければ質問（1文で。例:「AIが人間の思考速度を拡張する」） | テキスト（自由記述） |

**残りの `{{ }}`（主役オブジェクト・矛盾した性質・場面・構図・撮影表現・素材・色・時間）は
ディレクターが3案 A/B/C の中で設計し、案の選択を通じて決まる**（全項目をユーザーに質問しない）。
ユーザーが任意で指定した項目（色・スタイル・アスペクト比・主役等）があれば、その指定を全案で尊重する。

**運用ルール:**

- **充足判定は2項目共通**: 今回の依頼文・提供資料に**文字どおり**書かれ一意に読み取れる場合のみ「明示あり」。
  推定は明示ではない。質問を省いた項目は K0 で1行列挙して認識合わせする（黙って仮定しない）。
- **K0 に既存の必須ゲートを同梱する**: 生成前の**モデル宣言→承認**（SFW 既定＝Codex GPT Image。
  拒否・障害・サイズ不適合時は AtlasCloud Seedream にフォールバック）と、**アスペクト比の既定提案**
  （Xサムネ/LP FV/スライド表紙＝16:9 を既定として明示。Web背景等は用途に応じて提案）。
- **「任せる」は K0 質問への項目単位の回答**として成立する。包括的な「お任せ」「いい感じに」だけでは省略できず、
  K0 で仮定一覧を添えた1問で確認してから進む。
- **「質問不要/確認不要」は工程省略指示ではない。** 仮定一覧付きの1問だけは必ず行う。それも明示的に拒否されたら
  （無応答は拒否ではない — 応答を待つ）**通知型**に切り替える: K1相当（3案の設計＋生成＋比較。案選択はエージェントが行い
  選定理由を明記）→ K2相当（改善版＋監査結果）を提示し「次の発言までに異議がなければこの仮定で進む」と明示。
  納品は監査結果の提示とは**別メッセージ**（ユーザーが介入可能なターン境界を挟む）。
- **質問できない実行形態**（サブエージェント・ヘッドレス等）では、案選択を呼び出し元へ委譲する。
  実装まで進めるのは【ブリーフ完備（人間ユーザーの回答の転記である旨の明記）】かつ【案選択の委任明記】の両方を
  満たす場合のみ — 欠ければ3案の設計と生成プロンプトを成果物として返して停止する。

【主役となるオブジェクト】{{例：透明な立方体}}
【主役に与える矛盾した性質】
{{例：固体でありながら、内部が液体のように流動している}}
この矛盾は奇抜さのためではなく、{{概念との関係}}を視覚化するために使用する。

【場面】{{例：暗い無機質な展示空間の中央}}

【構図】
・主役は画面の{{中央／右側／左側}}
・画面内の占有率は{{60％}}

【撮影表現】

・被写界深度は{{浅い／中程度／深い}}
・光源は{{大きな拡散光、側面光、逆光など}}
・過度なHDR表現を避ける
・ハイライトを白飛びさせず、暗部にも素材情報を残す

【素材】
・{{ガラス、金属、布、木材、液晶、紙など}}
・表面に微細な傷、反射、透過、厚みを持たせる
・プラスチックのような均一な質感にしない
・素材ごとの光の反応を物理的に整合させる

【色】
・基調色：{{入力}}／補助色：{{入力}}／アクセント色：{{入力}}
・色数を制限し、主役の形と素材を優先する

【時間・変化】
静止画でありながら、
{{溶ける直前、割れた直後、形成途中、呼吸している瞬間}}
のような時間の途中を感じさせる。

【品質基準】
・広告制作会社が納品できる完成度／主役が一目で分かる

## §3 統合マップ（対話ラウンド K0〜K2）

工程は**既定**。省略できるのは、ユーザーが**工程名を特定して**省略を指示した時だけ
（例:「3案は不要、1案で」「監査は飛ばして」。「急ぎ」「シンプルに」「お任せ」は省略指示ではない —
該当しそうな発言があったら工程名を挙げて確認する。確認は1発言につき最大1工程・一括省略の提案禁止・
同意応答を足がかりに次の省略確認を連鎖させない）。

| ラウンド | 内容 | 形式 |
|---------|------|------|
| K0 | ブリーフ2項目ゲート（§1）＋モデル宣言→承認＋アスペクト比・スタイル既定の明示 | AskUserQuestion＋テキスト |
| K1 | **3方向ディレクションの設計提示 → A/B/C 各1枚を順次生成 → 3枚＋比較表を提示・選択** | SendUserFile＋AskUserQuestion |
| K2 | 選択案の**改善版1枚**を生成 → **プロ級監査（下記・暫定仕様）** → 監査結果と共に提示・納品 | SendUserFile＋テキスト |

**K1 の設計提示（各案の最低要素）**: 主役オブジェクト／矛盾した性質と**概念との関係**（奇抜さでなく視覚化 — 説明できなければ選び直す）／
場面／構図（主役位置・占有率・**コピースペースの位置と比率**）／撮影表現（アングル・レンズ・被写界深度・光源）／
素材／色（基調・補助・アクセント）／時間の瞬間 ＋ **生成プロンプト全文**。
A/B/C は正本の方向性定義（写実／物理反転／古典×デジタル）の差を必ず保ち、
**主役オブジェクト・矛盾・素材のうち2つ以上が案間で異なる**こと（実質同一の3案は工程未実施扱い）。
生成は**1枚ずつ順次**（各生成後に軽検品: 文字/ロゴ/透かし混入・破綻・アスペクト比）。
比較表は**独自性・可読性・用途適合性・素材整合性**の4軸（正本準拠）で3案を評価し、推奨案と理由を添える。

**K2 のプロ級監査（暫定仕様 — ユーザーの「プロ級監査ブロック」本文受領まで）**: 改善版に対し次を検査し、
各項目に判定＋1行根拠（画像上の具体箇所）を付けて提示する:

1. **主役の一目認識・縮小識別**: サムネイル相当（幅 ~200px）に実際に縮小してシルエットが識別できるか
2. **コピースペースの成立**: 設計した位置・比率の余白が均質で、コピーを重ねられるか
3. **素材整合性**: 光の物理反応・質感の整合。過度な HDR・白飛び・暗部潰れがないか
4. **【避ける表現】非該当**: 発光ライン／粒子／ネオン／回路模様／不自然な反射／無関係な人物／既視感AIアート／説明不能な装飾
5. **文字・ロゴ・透かし混入なし**（既存恒久ルールと二重に効かせる）
6. **用途適合**: アスペクト比・プラットフォーム・トーンが K0 の用途に合うか

**停止級**（該当したら再生成してから提示する）: 文字/ロゴ/透かしの混入・主役が不明・コピースペース不成立・
【避ける表現】の明白な該当。全項目合格でも、最もリスクが高い上位2項目を名指しし根拠を書く
（具体箇所の引用が無い「問題なし」は判定として数えない）。監査は生成物ごとに独立に行い、K1 の比較で代替しない。

**既存ルールとの整合:**

| 既存ルール | 本フローでの扱い |
|-----------|----------------|
| ★文字を入れない（恒久） | そのまま適用。正本【品質基準】「文字、ロゴ、透かしを生成しない」と同旨で二重に効く |
| ★スタイル既定＝リアル | A案（写真として現実に存在しそうな案）が担う。B/C 案は正本の方向性が優先 — リアル化スターターは写実表現の案にのみ適用し、案の表現意図と矛盾する項目は足さない |
| モデル宣言→承認 | K0 に同梱（SFW 既定＝Codex GPT Image → フォールバック AtlasCloud Seedream） |
| ★seed ランダム化 | そのまま適用（3案は方向・プロンプト自体が違う。改善版も seed 固定しない） |
| 検品→SendUserFile | 各生成後に軽検品、K1/K2 の提示は SendUserFile |
| ★品質優先（CLAUDE.md 重大ルール） | 解像度・品質設定を速さのために勝手に下げない |
| ★1本ルール | **本フロー対象外**（冒頭の分離宣言。リアル人物・動画では従来どおり有効） |

**増分変更**: 納品後の修正は、変更点を設計に反映→再生成1枚→**監査を再実施**してから提示。
用途・概念が変わる依頼は K0 から通す（ブリーフは差分のみ確認）。

## §4 省略の合理化と反論（RED 実測 2026-07-21）

| 合理化（実測の言い回し） | 反論 |
|------------------------|------|
| 「概念設計・3方向比較・改善版・品質監査はスキル本文に規定が存在しない」 | 本書がキービジュアル用途の既定フローとして規定する |
| 「3方向同時生成は『★生成は一度に1本だけ』の恒久ルールに違反する」 | 1本ルールはリアル人物画像・動画用（2026-07-21 ユーザー確定で分離）。KV は 3案＋改善版＝計4枚が既定。ただし順次生成・各軽検品は維持 |
| 「『いい感じに任せる』だから用途・概念も聞かない」 | 用途・概念は必須ゲート。お任せは仮定一覧付き1問を経て成立する |
| 「用途は聞かず 16:9 で作れば潰しが効く」 | 用途はコピースペース・構図・監査基準を決める入力。必須質問 |
| 「コピースペースは実装側（HTML/スライド）の都合だから画像では不要」 | 正本【構図】の要件であり監査項目。設計して残す |
| 「避ける表現リストは実写自然化プロンプトで代替済み」 | 別物。自然化＝実写のAIっぽさ対策、避ける表現＝抽象KVのAIアート定番対策。両方適用する |
| 「3案は色違いで出せば速い」 | A/B/C の方向性差＋主役/矛盾/素材のうち2要素以上の差が必須。実質同一は工程未実施扱い |
| 「監査ブロックは本文が届いていないから監査は不要」 | §3 K2 の暫定仕様が代替する。未受領は監査を飛ばす理由にならない |
| 「比較表を書いたから監査も済んだ」 | K1 比較（案の選定）と K2 監査（完成物の検査）は別工程。相互に代替しない |

## Red Flags — これが頭をよぎったら止まる

- 「用途は聞かなくても汎用に作れば使い回せる」
- 「3案が結局似てしまったが、比較表で差があるように書けばよい」
- 「発光パーティクルとネオンを足せばそれっぽく見える」（避ける表現の定番）
- 「サムネ縮小チェックは目視省略でよい」（実際に縮小して見る）
- 「監査ブロック本文が無いから何もしなくていい」

**いずれも: 手を止めて §1 の未充足項目を質問し、§3 の工程に戻る。**
