slide-making / ui-ux-design（LP・サイト）のフローからキービジュアルが必要になった場合も本フローで生成する。

**★1本ルールとの関係（2026-07-21 ユーザー確定）**: 「★生成は一度に1本だけ」は**リアル人物画像・動画生成の規律**であり、

軽検品・監査で**不合格になった枚は4枚上限に数えない** — 不合格枚は必ず再生成してから提示する（1枚ずつ・都度軽検品。

## §1 ブリーフ2項目ゲート（必須質問）＋ディレクター設計項目

§2 の `{{ }}` のうち、**ユーザーに必ず質問するのは次の2項目だけ**（2026-07-21 ユーザー確定）。
未指定なら着手前に質問する。「任せる」「業界的に自明」「急ぎ」は省略理由にならない。

| # | 項目 | 充足の判定 | 聞き方 |
|---|------|-----------|--------|
| 1 | 用途 | 依頼文から**一意に**読み取れれば充足（K0 で1行明示して認識合わせ）。読み取れなければ質問 | AskUserQuestion（Xサムネイル/LPファーストビュー/スライド表紙/Web背景＋Other ※1問の選択肢は4つまで） |
| 2 | 伝えたい概念 | 明示がなければ質問（1文で。例:「AIが人間の思考速度を拡張する」）。視覚モチーフの指定（例:「データが水のように流れる」）は概念の明示ではない | テキスト（自由記述） |

**残りの `{{ }}`（主役オブジェクト・矛盾した性質・場面・構図・撮影表現・素材・色・時間）は
ディレクターが3案 A/B/C の中で設計し、案の選択を通じて決まる**（全項目をユーザーに質問しない）。
ユーザーが任意で指定した項目（色・スタイル・アスペクト比・主役等）があれば、その指定を全案で尊重する。

**運用ルール:**

- **充足判定は2項目共通**: 今回の依頼文・提供資料に**文字どおり**書かれ一意に読み取れる場合のみ「明示あり」。
  推定は明示ではない。質問を省いた項目は K0 で1行列挙して認識合わせする（黙って仮定しない）。
- **K0 に既存の必須ゲートを同梱する**: 生成前の**モデル宣言→承認**（SFW 既定＝Codex GPT Image。
  拒否・障害・サイズ不適合時は AtlasCloud Seedream にフォールバック）と、**アスペクト比の既定提案**
  （Xサムネ/LP FV/スライド表紙＝16:9 を既定として明示。Web背景等は用途に応じて提案）。
- **K0 完了（用途・概念の回答受領＋モデル承認）までは、A/B/C を含む一切の案画像を生成しない。**
  SKILL.md の「試作用の静止画キーフレーム生成は承認前に続けてよい」の例外は**動画フローのキーフレーム限定**であり、
  本フローには適用しない。
- **「任せる」は K0 質問への項目単位の回答**として成立する。包括的な「お任せ」「いい感じに」だけでは省略できず、
  K0 で仮定一覧を添えた1問で確認してから進む。
- **「質問不要/確認不要」は工程省略指示ではない。** 仮定一覧付きの1問だけは必ず行う。それも明示的に拒否されたら
  （無応答は拒否ではない — 応答を待つ）**通知型**に切り替える。**通知型でも承認前生成の禁止は維持する**:
  ①モデル宣言＋仮定一覧を提示して**ターンを終了**し、**ユーザーの次の発言**までに異議がなければ次ターンで生成に進む
  →②K1相当（3案の設計＋生成＋比較。案選択はエージェントが行い選定理由を明記）→③K2相当（改善版＋監査結果）を提示して
  **ターンを終了し制御をユーザーに返す**→④納品は**その後の別ターン**でのみ行う。
  「次の発言」は**ユーザーの**次の発言を指し、同一ターン内の連続送信は「別メッセージ」「異議機会」に該当しない。
- **質問できない実行形態**（サブエージェント・ヘッドレス等）では、案選択を呼び出し元へ委譲する。
  生成（K1/K2 の実行）まで進めるのは【ブリーフ完備（**人間ユーザーの回答の転記**である旨の明記）】かつ
  【案選択の委任明記】かつ【使用モデルの承認の転記明記】の**3つすべて**を満たす場合のみ — 欠ければ3案の設計と
  生成プロンプトを成果物として返して停止する。SKILL.md の「無人の自律パイプライン」例外は列挙済みの既存パイプライン
  （phase1_generate.mjs・sheet-factory 等）に限り、**本フローの実行形態を無人パイプラインと自己分類して適用しない**。

## §3 統合マップ（対話ラウンド K0〜K2）

工程は**既定**。省略できるのは、ユーザーが**工程名を特定して**省略を指示した時だけ
（例:「3案は不要、1案で」「監査は飛ばして」。「急ぎ」「シンプルに」「お任せ」「1枚で」は省略指示ではない —
該当しそうな発言があったら工程名を挙げて確認する。確認は1発言につき最大1工程・一括省略の提案禁止・
同意応答を足がかりに次の省略確認を連鎖させない）。
**省略は名指しされた工程のみに効き、残工程は維持する** — K1（3案比較）を省略した場合は生成した1案を
「選択案」とみなし、改善版の要否のみ1問で確認したうえで **K2 監査は必ず実施する**
（監査が消えるのは「監査は飛ばして」と名指しされた時だけ）。

| ラウンド | 内容 | 形式 |
|---------|------|------|
| K0 | ブリーフ2項目ゲート（§1）＋モデル宣言→承認＋アスペクト比・スタイル既定の明示。**完了まで生成0枚** | AskUserQuestion＋テキスト |
| K1 | **3方向ディレクションの設計提示 → A/B/C 各1枚を順次生成 → 3枚＋比較表を提示・選択** | SendUserFile＋AskUserQuestion |
| K2 | 選択案の**改善版1枚**を生成 → **プロ級監査（下記・暫定仕様）** → 監査結果と共に提示・納品 | SendUserFile＋テキスト |

**K1 の設計提示（各案の最低要素）**: 主役オブジェクト／矛盾した性質と**概念との関係**（奇抜さでなく視覚化 — 説明できなければ選び直す）／
場面／構図（主役位置・占有率・**コピースペースの位置と比率**）／撮影表現（アングル・レンズ・被写界深度・光源）／
素材／色（基調・補助・アクセント）／時間の瞬間／**仕上げ様式（写実レンダー or 様式化）**＋**生成プロンプト全文**。
**生成プロンプトには【品質基準】【避ける表現】由来の回避指示を必ず含める**（negative 対応モデルは negative に、
非対応モデルは正の回避文で）。A/B/C は正本の方向性定義（写実／物理反転／古典×デジタル）の差を必ず保ち、
**主役オブジェクト・矛盾・素材のうち2つ以上が案間で異なる**こと（実質同一の3案は工程未実施扱い）。
生成は**1枚ずつ順次** — 各生成後に**軽検品**: 文字/ロゴ/透かし混入・破綻・アスペクト比・**【避ける表現】の明白な該当**
（不合格は提示前に再生成。不合格枚は4枚上限に数えない）。
**比較表は3枚の生成・軽検品完了後にのみ作成**し、独自性・可読性・用途適合性・素材整合性の4軸（正本準拠）で評価。
各案の評価（最低でも最強軸・最弱軸と推奨理由）に**生成画像上の具体箇所を引用する** — 引用の無い評価は判定として数えない。

**K2 のプロ級監査（暫定仕様 — ユーザーの「プロ級監査ブロック」本文受領まで）**: 改善版に対し次を検査し、
各項目に判定＋1行根拠（画像上の具体箇所）を付けて提示する。
**軽検品（文字/破綻/AR/避ける表現の3〜4点スクリーニング）は本監査の代替にならない** — 改善版には両方行う:

1. **主役の一目認識・縮小識別**: サムネイル相当（幅 ~200px）に実際に縮小してシルエットが識別できるか
2. **コピースペースの成立**: 設計した位置・比率の余白が均質で、コピーを重ねられるか
3. **素材整合性**: 光の物理反応・質感の整合。過度な HDR・白飛び・暗部潰れがないか
4. **【避ける表現】非該当**: 発光ライン／粒子／ネオン／回路模様／不自然な反射／無関係な人物／既視感AIアート／説明不能な装飾
5. **文字・ロゴ・透かし混入なし**（既存恒久ルールと二重に効かせる）
6. **用途適合**: アスペクト比・プラットフォーム・トーンが K0 の用途に合うか

**停止級**（該当したら再生成してから提示する。再生成枚は4枚上限外）: 文字/ロゴ/透かしの混入・主役が不明・
コピースペース不成立・【避ける表現】の明白な該当。全項目合格でも、最もリスクが高い上位2項目を名指しし根拠を書く
（具体箇所の引用が無い「問題なし」は判定として数えない）。監査は生成物ごとに独立に行い、K1 の比較で代替しない。

**既存ルールとの整合:**

| 既存ルール | 本フローでの扱い |
|-----------|----------------|
| ★文字を入れない（恒久） | そのまま適用。正本【品質基準】と二重に効く。ユーザーが文字入りを明示要求した場合も、コピーは画像に焼き込まず別レイヤー（slide-making の HTML/pptx・LP の実装側）で組む提案を既定とする。焼き込みをなお求められたら恒久ルールの明示例外として扱い、**正本フローの枠外である旨を宣言して**生成する（§2 自体は改変しない） |
| ★スタイル既定＝リアル | A案（写真として現実に存在しそうな案）が担う。**B/C 案も仕上げが写真的レンダーなら（内容の非現実性に関わらず）リアル化スターターを適用**（案の表現意図と矛盾する項目は足さない）。様式化レンダーで設計する場合のみ不適用 — 各案の仕上げ様式は K1 の設計提示に必ず明記する |
| モデル宣言→承認 | K0 に同梱（SFW 既定＝Codex GPT Image → フォールバック AtlasCloud Seedream）。通知型でも提示→ターン終了→異議なし確認の後にのみ生成（§1） |
| ★seed ランダム化 | そのまま適用（3案は方向・プロンプト自体が違う。改善版も seed 固定しない） |
| 検品→SendUserFile | 各生成後に軽検品、K1/K2 の提示は SendUserFile |
| ★品質優先（CLAUDE.md 重大ルール） | 解像度・品質設定を速さのために勝手に下げない |
| ★1本ルール | **本フロー対象外**（冒頭の分離宣言と人物境界。リアル人物が識別可能に写る画像は主役か否かを問わず従来どおり有効） |

**増分変更**: 納品後の修正は、変更点を設計に反映→再生成1枚→**監査を再実施**してから提示。
用途・概念が変わる依頼は K0 から通す（ブリーフは差分のみ確認）。

| 「A/B/C は選択前の試作だから承認前に生成してよい」 | K0 完了までは案画像を一切生成しない。試作例外は動画キーフレーム限定 |
| 「3案を1枚のグリッドにまとめれば生成1回で済む」 | 別ファイル・最終アスペクト比で1枚ずつ。グリッド生成は工程未実施扱い |
| 「コピースペースは実装側の都合だから画像では不要」 | 正本【構図】の要件であり監査項目。設計して残す |
| 「避ける表現リストは実写自然化プロンプトで代替済み」 | 別物。自然化＝実写のAIっぽさ対策、避ける表現＝抽象KVのAIアート定番対策。両方適用する |
| 「3案は色違いで出せば速い」 | A/B/C の方向性差＋主役/矛盾/素材のうち2要素以上の差が必須。実質同一は工程未実施扱い |
| 「各生成後に軽検品したから監査も済んだ」 | 軽検品は3〜4点スクリーニングのみ。監査6項目は別工程で、改善版には両方行う |
| 「比較表を書いたから監査も済んだ」 | K1 比較（案の選定）と K2 監査（完成物の検査）は別工程。相互に代替しない |
| 「監査ブロックは本文が届いていないから監査は不要」 | §3 K2 の暫定仕様が代替する。未受領は監査を飛ばす理由にならない |
| 「『1案で』と言われたから K2（改善版＋監査）も消える」 | 省略は名指しされた工程のみ。K1 省略でも K2 監査は必ず実施する |
| 「本数上限があるから不合格枚は再生成せず提示する」 | 不合格枚は上限に数えない。必ず再生成してから提示する |

## Red Flags — これが頭をよぎったら止まる

- 「用途は聞かなくても汎用に作れば使い回せる」
- 「3案が結局似てしまったが、比較表で差があるように書けばよい」
- 「比較表は設計段階の記述から先に書いてしまおう」（生成画像を見ずに評価）
- 「発光パーティクルとネオンを足せばそれっぽく見える」（避ける表現の定番）
- 「サムネ縮小チェックは目視省略でよい」（実際に縮小して見る）
- 「監査ブロック本文が無いから何もしなくていい」
- 「人物が入るが主役じゃないから4枚作ってよい」（人物境界の逆用）

**いずれも: 手を止めて §1 の未充足項目を質問し、§3 の工程に戻る。**
