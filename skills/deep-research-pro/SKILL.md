# Deep Research Pro — 集めるだけでなく、検証を通さないと出荷できない調査

## これは何か

深い調査を、**モデルの善意ではなく構造で**担保するパイプライン。
`Workflow` スクリプトで順序が固定され、機械的な検査を通らないレポートは出荷されない。

## まず: 本当にこれが要るか

このハーネスには**組み込みの `deep-research` ワークフロー**が既にある（`Workflow({name: "deep-research", args: "<質問>"})`）。
最大15ソースを取得し、上位25クレームを3票の敵対的反証にかけ、構造化JSONを返す。**軽い調査はそれで足りる。**

| 依頼 | 使うもの |
|---|---|
| 事実1つ・短い調べ物 | 標準の WebSearch / WebFetch |
| 一般的な調査・要点の把握 | 組み込み `deep-research`（軽い・速い） |
| **賛否が割れる論点を評価して立場を決める** | **本スキル** |
| **意思決定・資金申請・投稿の根拠になる調査** | **本スキル** |
| **セッションをまたいで積み上がる調査** | **本スキル**（vault が残る） |
| arXiv 検索・論文PDFへのQ&A | `alphaxiv` |
| PubMed/ChEMBL/UniProt 等のツール実行 | `research-toolkit` |

本スキルは学術検索そのものを作り直さない。`research-toolkit` / `alphaxiv` は**この中から呼んで使う**。

## 2つの土台（ここが組み込み版との差）

### 1. ツールロックは指示より強い

参照元（hyperresearch）の設計ノートによれば、「再生成せず差分だけ当てろ」は、
担当が**物理的に Write を持たない**ときだけ守られた。
プロンプトの禁止事項は、圧がかかると破られる。だから:

- `dr-patcher` のツールは `Read` と `Edit` **だけ**（レポートを作り直せない）
- `dr-critic` は `Edit` も `Bash` も**持たない**（見つける人と直す人を分ける）
- `dr-runner` は `Bash` と `Read` **だけ**（コマンドを走らせる以外できない）

**機械で強制できる不変条件は、機械で強制する。** プロンプトは助言でしかない。

`Bash` まで外しているのが要点。`Edit` だけ取り上げても `Bash` が残っていれば
シェル経由で書けるので、「批評者はレポートを変更できない」という性質が成立しない。
**迂回路を全部塞いで初めてロックになる**（`ToolSearch` も同様に外す）。

### 2. 出荷ゲートは1コマンド。継ぎ目を作らない

検査を個別コマンドに分けると、モデルは失敗を「誤検知」と再解釈して出荷する。
参照元では、lint が幻覚引用24件を検出したのに「誤検知だ」と自分宛のメモを書いて
そのまま出荷した事例が記録されている。だから検査は `shipgate.py` 1本に閉じる。

**この機で実測した挙動**: 幻覚引用を1つ仕込んだレポート → exit 1（`verbatim_quotes` で捕捉）。
撤回論文を無断引用したレポート → exit 1（`retracted_sources` で捕捉）。正常なレポート → exit 0。

**ゲートの判定は事実であって、評価の対象ではない。**
落ちたら**レポートを直して**再実行する。検査を個別に回して「これは誤検知」と論じる経路は無い。
規定回数直しても通らなければ `blocked` のまま正直に報告する。
嘘をつくレポートを出荷するより、止まったまま正直な方がよい。

## 使い方

### 先に確認すること（初回・実測で必要）

このパイプラインはツールロックされたサブエージェント（`dr-fetcher` / `dr-critic` /
`dr-patcher` など）に依存する。**エージェントの登録はセッション開始時にしか読まれない。**
`~/.claude/agents/dr-*.md` を置いた直後の同じセッションでは
`Agent type 'dr-patcher' not found` になる（実測）。

初回は **Claude Code を再起動してから**実行すること。
実行前に、使えるエージェント一覧に `dr-` で始まるものが並んでいるか確認する。
解決できないまま走らせると、途中で止まる。

### 実行

```
Workflow({
  scriptPath: "C:/Users/u8792/.claude/skills/deep-research-pro/workflow.js",
  args: "<ユーザーの質問を1文字も変えずに>"
})
```

vault は**作業中プロジェクト直下の `./research/`** に作られる。次回以降の調査は、
取得する前にまず vault を探す（だからセッションを重ねるほど速く・厚くなる）。

`~/.claude` 配下では実行しない（GitHub 公開同期されるため調査内容が公開される）。
調査用の作業ディレクトリで実行すること。

### tier

| tier | 中身 | 目安 |
|---|---|---|
| `standard` | 収集→検証→ドラフト1本→批評→パッチ→cite-check→ゲート | 数十ソース |
| `deep` | 上記＋対立グラフ・争点ごとの深掘り・ドラフト3本→統合 | 賛否が割れている主題 |

判断に迷ったら**上げる**（浅すぎる報告の損害の方が大きい）。ただし全部を `deep` にしない。

## 実測された抜け道と、その反論

以下は**スキルなしで同じ調査課題を回したときに実際に出た言い訳**（2026-07-26 実測）。
思い浮かんだら手を止める。

| 言い訳（実測・逐語） | 現実 |
|---|---|
| 「defensible な立場を取るには十分だ」 | ソース3件で言った台詞。十分だと判定したのは、やめたい側 |
| 「もう強力なシステマティックレビューの証拠がある」 | 最初の2コールで言った。**反証を探す前に構造が固まっている**＝アンカリング |
| 「web 検索の方が同じ主要試験を速く出す」 | 取得済みの学術API結果10万字を一度も開かずに言った |
| 「抄録＋業界紙の要約で同じ数字が得られる」 | 得られない。数値と方法は本文にしかない。ペイウォールは代替経路を試してから諦める |
| 「WebFetch が引用箇所を抽出済みだから逐語のはず」 | **違う。WebFetch は小型要約モデル経由で、逐語保証がない。** 引用符に入れてよいのは自分が本文で見た文字列だけ |
| 「検索スニペットに効果の向きが書いてあるから十分」 | 効果量を見ていない研究を引用したことになる |
| 「レポートが自分で限界を開示しているから批評者も同じ指摘しかしない」 | **開示は検証の代用にならない。** 穴を書き添えても穴は埋まらない |
| 「絵が整合したので検索をやめた」 | やめる基準は「整合したとき」ではなく「新しい検索が新情報を返さなくなったとき」 |
| 「自分で立場を書き、自分で反論節を書いた」 | それは自己採点。反論節を書いた本人は、その反論の甘さを見つけられない |
| 「取得しやすい文献ばかり集まったが、結論は変わらないだろう」 | 変わる。安心side が公開されていて批判side が有料なら、非対称が結論を作る |

**「最大限に厳密にやって」と明示的に指示しても、独立した批評パスは発生しなかった**（実測3/3）。
だから頼むのではなく、パイプラインに組み込む。

## 止まるべき合図

- 「ソースは十分集まった」と、カバレッジ検査を見ずに思った
- ペイウォールに当たって、代替経路を試さずに抄録で代用しようとしている
- 取得ツールの要約が返した文を、引用符に入れようとしている
- 批評の指摘を、パッチ担当を通さず自分で直そうとしている
- ゲートが落ちたので、検査の妥当性を検討し始めた
- 「両論あります」で終わる中間ノート／レポートを書いている

**全部「構造に戻れ」の合図。**

## このパイプラインができないこと

- **事実の正しさは保証しない。** 検査が見るのは構造と結合（引用がその文を支持しているか、
  引用符の中身が出典に逐語で存在するか、撤回論文を無断で引用していないか）。
  出典自体が間違っている可能性は残る。
- ログインしていないペイウォールの中は読めない。
- CAPTCHA・2要素認証・ログインの自動突破は**やらない**（恒久的にスコープ外）。
- どのソースが重要かの最終判断は人間のもの。パイプラインは選び、人間が舵を取る。
