# なぜこの検査があるのか

検査は思いつきではなく、**実際に起きた失敗**に対応している。
緩める判断をする前に、その検査が何を止めていたかをここで確認すること。

## 1. 逐語引用の実在検査（`verbatim_quotes`）

**やること**: レポート中の引用符（`"…"` `“…”` `「…」` `『…』`）に囲まれた全スパンが、
保存済みの出典本文に**逐語で存在する**かを照合する。1つでも無ければ落とす。

**止めているもの**: 実在する論文を根拠に、その論文が言っていない文言を引用符付きで書くこと。

**なぜ必要か**: 実測で、調査エージェントは `WebFetch` が返した文をそのまま引用符に入れる。
しかし `WebFetch` は**小型の要約モデル経由**で答えるので、返ってくる文字列は原文とは限らない。
ベースライン実測でエージェント自身がこう書いている —
「WebFetch が引用箇所を抽出済みだから逐語のはず、と自分に言った。だが引用符を打ったのはページではなくモデルだ」。

**運用上の含意**: 引用符は**逐語のときだけ**使う。比喩や強調の引用符（いわゆる scare quotes）は
この検査に引っかかる。引用符を外して普通の文か強調にする。
これは検査の副作用ではなく意図した設計で、引用符の意味を1つに固定している。

**誤検知がほぼ無い**ので、初日から警告ではなくエラーにしてよい種類の検査。

## 2. 引用の解決検査（`citecheck_unresolved` / 未検証件数）

**やること**: レポートの (文, 引用) の組を抽出し、引用先を3状態に分ける。

| 状態 | 扱い | 理由 |
|---|---|---|
| どのノートにも解決しない | **critical・出荷を止める** | 捏造か破損した引用 |
| ノートは存在するがクレーム未抽出 | **止めない。件数を報告** | レポートの欠陥ではない |
| ノートもクレームもある | 機械照合 → 残りを判定へ | — |

**なぜ3状態なのか**: 当初は2状態で、**クレーム未抽出のノートを引用すると
「捏造引用」と判定されて出荷が止まっていた**（2026-07-27 実測）。
これは全く違う2つの失敗の混同で、正しく書かれたレポートが通らなくなる。
一方で「引用先が存在しない」を緩めてはいけない。そこがこの検査の中核。

**機械トリアージ**: LLM に全ペアを見せるのは高すぎるので、先に機械で自動通過させる。

- クレームの**逐語引用が文中に現れる** → 自動通過
- 文中の**すべての数値**が引用先クレームの数値に含まれる → 自動通過

**「すべての」が要点。** 1文に数値が2つあり出典が片方しか支持しない、という失敗が実在する。
「概ね合っている」で通すと捕まらない。部分一致は自動通過させず判定に回す。

**残りの標本抽出は決定的**（乱数を使わない）。再開したときに同じ標本を見ないと、
監査の記録が実行ごとに変わってしまう。

### 文分割は自前で持っている（`sentence_split.py`）

素朴な文分割は**小数点で文を割る**。`12.4` が `12.` と `4` に分かれると、
数値を含む文では上記の自動通過が**原理的に働かない**（2026-07-26 実測で `auto_pass=0`）。
数値を含む文こそ最も検証が要るので、これは致命的だった。

現在は小数・一般的な略語（`et al.` `U.S.` `Fig.` 等）で割れず、
日本語の句点でも割れ、文末直後の引用マーカーはその文に属したままになる。
`shipgate` の引用密度も同じ関数を使う。

## 3. 撤回検査（`retracted_sources`）

**やること**: 引用している出典に撤回フラグが立っていて、レポートが撤回に言及していなければ落とす。

**判定は3経路**: OpenAlex の `is_retracted` / PubMed の `"Retracted Publication"[Publication Type]` /
Crossref の `update-to`。**1つでも陽性なら撤回扱い**（見逃しより誤検出を選ぶ）。

**実測**: Wakefield 1998（`10.1016/S0140-6736(97)11096-0`）で OpenAlex と PubMed の
2経路が一致。対照の非撤回論文では3経路とも陰性。

**なぜ出荷時に再確認するのか**: 撤回は後から起きる。集めた時点で健全でも、
出荷時点では撤回されていることがある。キャッシュではなくその場で照会する。

**撤回に言及したうえで論じるのは正当**。この検査が止めるのは「無断で根拠に使う」ことだけ。

## 4. 独立性監査（syndication）

**やること**: ソースを3経路でクラスタ化し、クラスタ代表以外の重みを下げる。

| 経路 | 見るもの |
|---|---|
| URL正規化 | トラッキングパラメータ除去・www除去・末尾スラッシュ除去後の同一性 |
| ワイヤー署名 | 本文冒頭の通信社マーカー（Reuters/AP/AFP/PR Newswire/Business Wire 等）＋冒頭本文のハッシュ |
| 本文類似度 | 単語 n-gram の Jaccard 係数が閾値以上 |

**代表は独立性 1.0、他のメンバーは 1/クラスタサイズ。**

**なぜ必要か**: 「独立した3件以上のソースが一致している」は強い証拠だが、
**1本のプレスリリースの5転載は5件の一致ではなく1つの声**。
件数で数えると合意が水増しされ、確信が実態より高く出る。

**実測**: 同一ワイヤー記事の4転載 → 独立性の和 **1.75**（代表1.0＋0.25×3）。
同じ corpus の中で、独立した試験論文と批判論文はそれぞれ 1.0 のまま。

**ワイヤー署名は本文の冒頭で取る。タイトルではない。**
転載先はタイトルを付け替えるが、ワイヤー本文そのものは変えないため。

## 5. 品質スコア

出典種別・被引用数・透明性（DOI/著者/日付/方法の有無）・査読の有無・新しさの加重和。
**撤回が立っていれば他を無視して床値**にする。

**欠けている成分は0点にせず、存在する成分だけで正規化する。**
0点にすると、DOI や被引用数を持たない非学術ソース（政府統計・一次データ）を
不当に沈めてしまうため。

## 検査が保証しないこと

**事実の正しさは判定しない。** 見ているのは構造と結合だけ。

「引用符の中身が出典に逐語で存在する」ことは検証できるが、
**その出典自体が間違っている可能性**は残る。そこは人間の担当。

この境界を曖昧にすると、「ゲートを通ったから正しい」という最悪の誤読が生まれる。
ゲートが言えるのは「**嘘の引用は含まれていない**」までで、「内容が正しい」ではない。
