# 凍結中 — 実行しないでください

このディレクトリの `workflow.js` と `agents/` は **2026-07-27 に凍結**しました。
動きません。実行すると `~/.claude` 配下にファイルを散乱させます。

`agents/` の定義はここに置いてある限り**エージェントとして登録されません**
（登録されるのは `~/.claude/agents/` 直下のみ）。意図的にそうしています。

## 何が起きたか（実測・2026-07-27）

同じ問い（GLP-1 受容体作動薬と骨格筋量）を、組み込みの `deep-research` と
この `workflow.js` の両方に投げて比較しました。**このパイプラインは完走しませんでした。**

### 失敗1: vault が別の場所に作られる

ワークフローには作業ディレクトリを**絶対パスで**渡していました。
しかし収集エージェントへの指示文が相対パスで書かれていたため
（「`./research/sources` を確認し、`./research` 配下に保存せよ」）、
エージェントは**自分の cwd** でそれを解決しました。

結果、vault は `~/.claude/skills/deep-research-pro/research/` に作られました。
**スキル本体が「ここには置くな（GitHub 公開同期されるため）」と警告している、まさにその場所です。**
ワークフロー側は渡された作業ディレクトリを見続けるので、そちらは永久に空のままでした。
1回の実行で 605 ファイルが `~/.claude` 配下に散乱しました。

### 失敗2: エージェントが vault の API を使わない

誤配置先ですら `sources/` と `claims/` は**空**でした。
収集エージェントは提供した `vault.py`（`write_note` / `write_claims`）を一切呼ばず、
`curl` と自作の Python スクリプトで独自に収集し、生の抄録を `raw/` に、
スクリプトを `work/` に書いていました。

つまり、**下流の機械的検証層が要求する形式のデータがどこにも生成されませんでした。**
ゲートは立っているのに、そこまで荷物が届かない状態です。

### 失敗3: 遅い

70分回して収集フェーズを抜けられませんでした。
同じ時間で組み込み `deep-research` は収集を終えて検証フェーズに入っています。

## 動いていた部分（記録として）

全部が駄目だったわけではありません。次は設計どおり動いていました:

- F1（分解・tier分類・逐語クエリの保存）と vault 初期化・パッチログ事前生成
- F2 の3レンズ探索計画（`academic_topic: true` を判定し、学術APIチャネルに
  「semaglutide 2.4 mg body composition DXA substudy lean body mass STEP 1」等を配置）
- 学術API先行の実挙動（OpenAlex を被引用数ソート＋日付フィルタで叩き、
  Europe PMC を `ABSTRACT:` フィールドで絞る）。組み込み版は WebSearch のみなので、
  ここは質的に違う
- エージェント未登録時に黙ってフォールバックせず停止する設計

## 再開するなら直すこと

1. **エージェントへ渡すパスを全部絶対パスにする。** 相対パスはエージェントの cwd で解決される。
2. **収集を `vault.py` 経由に強制する。** 自由記述で「保存せよ」と書くとエージェントは自作する。
   保存経路をコマンド1本に固定し、その戻り値でしか次に進めないようにする。
3. **収集フェーズの所要時間を測ってから広げる。** 現状の探索計画は1回の実行に対して重すぎる。

## 教訓

**エージェントに「〜に保存せよ」と文章で頼むと、保存先も保存形式も守られない。**
機械的な検証層をいくら固くしても、そこへデータを届ける経路が自由記述なら、
パイプラインは成立しない。ツールロックと同じ発想で、
**保存は「その1本しか呼べない」形にする必要がある。**
