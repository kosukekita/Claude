# AIアフィリエイト（ルカ式）

## 核心原則

**案件を知っただけでは1円にもならない。「すでに興味がある人（顕在層）だけをどう集めるか」がすべて。**
ここでの顕在層＝**もう申し込みたい人**。情報収集層・比較検討層は含まない（この読み替えを緩めると鉄則2が骨抜きになる）。

方法論は3点セット: **低ハードル案件 × AIで記事量産 × 顕在層キーワード集客**。スキマ時間（1日30分〜2時間）で月10万→30万を狙う設計。

> 出典: @ruka_affi（ルカ式）過去1年分の主要ツリー統合（2026-07取り込み）。

## いつ使うか

- アフィリエイトで稼ぎたい・案件を選びたい・記事を書きたいという相談すべて
- 「副業で月5万」のような収益目標相談で、集客手段がブログ/記事になりうる時
- **使わない場面**: 自社プロダクトの販売（business-validate-before-building）、SNS運用自動化そのもの（sns-auto-posting）

## 鉄則（この5つを外すと一般論SEOブログ指南に退化する）

1. **0→1は低ハードル案件で取る。「最初から中〜高単価を狙え」は初心者には誤り。**
   成果条件が「LINE追加・アプリDL・無料登録・資料請求」**だけ**の案件を選ぶ。読者に金を払わせる必要がない＝成約率が桁違いに高い。高単価（買わせる案件・来院案件）への移行は 0→1 達成後の横展開フェーズでやる。
2. **キーワードは顕在層から逆算する。「競合が弱いロングテール」という競合軸で選ばない。**
   軸は「**もう申し込みたい人が今まさに打つ言葉**」＝申込直前語（例:「退職代行 即日」「転職相談 LINE 無料」「(アプリ名) クーポン 招待コード」）。競合が弱いのは副産物であって選定理由ではない。情報収集層向けビッグワード（「転職 やり方」等）は0→1では狙わない。「〇〇 おすすめ」等の比較検討語は横展開フェーズの高単価ジャンル（例:「AGA 治療 おすすめ」）で使う顕在層語で、0→1の主戦場ではない。
3. **記事には型がある。** 「**悩み→共感→解決→申し込み**」の流れで**約3,000字**。切り口は①口コミ・評判 ②ランキング ③セルフチェック の3形式から案件に合うものを選ぶ。**字数は自己申告禁止・実測必須**: 記事を出す前に空白除外で実カウントし（許容 2,500〜3,500字）、未達なら加筆してから出す。実測せずに「約3,000字」とラベルを付けない。**記事本文はファイルに保存し、実測字数とファイルパスを明記して提出する**（第三者が再実測できる形にする）。
4. **AIを工程に組み込む（一発手書きしない）。** KW30個出し→記事生成→辛口改稿のループを回す（下のプロンプト集）。**改稿は証跡必須**: 「初稿の問題点→修正内容」の対応を最低3点、出力に残す。差分のない「反映済みです」は改稿していないのと同じ。
5. **「収益ゼロ3〜6ヶ月が普通」を既定にしない。** 低ハードル案件×顕在層KWの設計なら 0→1 は週単位で狙う。「半年は収益を見ない」という一般ブログ論に逃げて設計をゆるめない。

## 全体フロー（0→1→月10万→30万）

1. **スキマ時間を確保**（通勤・昼休み・帰宅後で30分〜2時間/日）。初期資金（PC等）が要るなら不要品をメルカリで売却
2. **大手ASP4社に無料登録**（審査ほぼなし・5分）: **A8net / もしもアフィリエイト / afb / バリューコマース**
3. **低ハードル案件を選ぶ**: 成果条件欄を確認し「追加・DL・無料登録・資料請求」だけで報酬が出るものに絞る。具体例と単価帯 → `references/offers-2026-07.md`
4. **AIで顕在層KW抽出 → 記事作成 → 辛口改稿**（下のプロンプト集）
5. **リンク設置・PR表記・公開**（下の法令チェック必須）
6. **横展開**: 成果が出たら同型案件を増やす。「記事を置いておくだけで成約が積み上がる」構造を案件数ぶん複製して月10万→30万へ

## AI活用プロンプト集（指示型・そのまま使う）

| 工程 | プロンプト |
|---|---|
| 案件探し | 「無料登録で報酬が出る案件を単価が高い順に20個」 |
| KW抽出（基本） | 「（商品/サービス）が欲しい人が検索するワードを10個出して」 |
| KW抽出（顕在層） | 「"もう申し込みたい人"が打つ言葉を30個」 |
| 記事作成 | 「悩み→共感→解決→申し込みの流れで3,000字程度で」 |
| 改善 | 「もっと申し込みが増えるよう辛口で直して」 |

- **切り口3形式**: ①口コミ・評判形式 ②ランキング形式 ③セルフチェック形式
- **ターゲット拡張**: 本人以外の検索者も狙う（例: AGAなら「旦那の薄毛」を調べる配偶者。「旦那 薄毛 気になる」も顕在層）

## 法令チェック（公開前必須）

- **ステマ規制（景表法）**: 記事冒頭に「※本記事にはプロモーションが含まれています」を明記
- **優良誤認（景表法・全ジャンル対象）**: 医療系でなくても、サービス実態の断定（「しつこい営業なし」「会社にバレない」「〇分で完了」「無料の理由は〜」等）はLP・公式の現物で裏取りしてから書く。未確認なら断定せず「LPで要確認」と明示する
- **薬機法・医療広告ガイドライン**: 美容・AGA・クリニック系で効果の断定NG（「治る」「必ず生える」等）。体験談も表現規制対象。**記事を書かない案件選定相談や横展開先の紹介であっても、医療・美容系ジャンルに触れる回答には必ずこの注意を一言添える**（「公開前チェック」限定にしない。GREEN検証で脱落が実発生）
- **事実の正**: 単価・成果条件・サービス内容はASP管理画面とLPの現物が正。憶測・古い記憶で書かない（提携解除リスク）
- **実字数カウント**: 空白除外で実測し 2,500〜3,500字に収める（鉄則3。実測値を明記してから公開）

## Common Mistakes（スキルなしエージェントの実測ベースライン）

| 実際に出た誤り | 正 |
|---|---|
| 「低単価案件で5万円はほぼ無理。最初から中〜高単価を狙うのが鉄則」 | 逆。0→1は低ハードル案件。単価を上げるのは横展開フェーズ |
| 「3〜4語の複合ロングテールで競合が弱い場所を狙う」（競合軸のみ） | 「もう申し込みたい人が打つ言葉」の意図軸で選ぶ。競合の弱さは副産物 |
| キーワードも記事も自力で一発書き（AI工程ゼロ） | AIにKW30個→3,000字生成→辛口改稿のループをさせる |
| 「まず20〜30記事・収益ゼロ半年が普通」の長期サイト設計論 | 1案件×数記事×顕在層KWで週単位の0→1を先に設計する |
| 記事本数の指示だけで1記事の型がない | 悩み→共感→解決→申し込み・約3,000字・切り口3形式 |
| ASP登録で4社のうち一部が漏れる | A8net・もしも・afb・バリューコマースの4社セットで案内 |
| 実測1,700字の記事に「約3,000字」とラベル（GREEN検証で実発生） | 出す前に空白除外で実カウント。2,500字未満なら加筆 |
| 「辛口改稿を反映済み」と自己申告のみ（差分なし） | 初稿の問題点→修正内容の対応を最低3点、出力に残す |

## Red Flags（言いそうになったら鉄則に戻る）

- 「最初から中〜高単価を狙いましょう」（0→1前に単価の話をしている）
- 「競合が弱いロングテールを狙いましょう」（意図軸の説明がない）
- 「半年は収益ゼロが普通です」（低ハードル×顕在層の設計を放棄している)
- AIプロンプトが工程に1つも出てこない回答を書いている
- 具体的な単価・案件名を記憶だけで断定している（→ references は時点データ、ASP現物確認へ誘導）
- 「約3,000字です」と書こうとしている（→ 実測したか？していないなら空白除外で測る）
- 「改稿済みです」と書こうとしている（→ 差分3点を示せるか？示せないなら改稿していない）
