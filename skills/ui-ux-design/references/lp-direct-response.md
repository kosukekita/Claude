# LP Direct Response — ui-ux-design

**LP（ランディングページ）作成の既定フローの正本。** ユーザー指定プロンプト（§2・2026-07-21 確定）を
LP制作の**既定フロー**として実行する。§2 の全文は**改変禁止**。
**§1・§3 は §2 と同格の必須規範であり、§2 の実行条件を定める（§2 単独では着手できない）。**
§2 に質問・承認工程が書かれていないのは §1・§3 がそれを担うためであり、
「正本に無い工程だから省略可」という読みは §4 の合理化に該当する。

**適用範囲**: 単一ページで特定の行動（購入/登録/相談/資料請求/応募等）への**転換を目的とする**ページの新規作成・
リニューアル（LP・セールスページ・オプトイン/キャンペーンページ・採用LP。既存サイトへの追加1枚でも該当）。
**分類は自称の目的でなく導線で判定する** — 単一ページに購入/登録/相談/資料請求/応募等への CTA・フォーム・
申込導線を**1つでも**置く成果物は転換目的とみなし本書が正本（「主目的は理解/紹介」等の自己判定でサイト行に
分類しない。ティザー・特設としてサイト行で扱えるのは**行動導線を持たない**ページのみ）。
ユーザーが LP かサイトかを明言していない単一ページ依頼では、迷いの有無にかかわらず分類確認の1問を必須とする。
**複数ページ構成の新規サイト**は `design-orchestrator.md` が正本。分類は依頼単位でなく**成果物単位**
（サイト＋LP混在依頼では LP 部分に本フローを通す）。
既存LPで「既存UI修正」ルートに乗せられるのは、訴求内容・構成・CTA・**価格や実績など実在情報の表示**の
いずれも変えない字句修正・誤字修正・固有名詞/日付の差し替えのみ（§3 軽微修正と同一定義）。
価格・実績・希少性表示（「残り◯名」「期間限定」等）の変更・追加は改修として L0 から通す
（本セッションで L4 承認済み仕様が現存する場合のみ §3 の増分パス）。

## §1 ブリーフ7項目ゲート（{{ }} 項目・未指定は必ず質問）＋固定指示2つ

§2 の `{{ }}` はプロジェクト毎に変わる入力。**未指定の項目は、着手前に必ずユーザーに質問して埋める。**
「フェーズ1 でエージェントが分析するから」「業界デフォルトで埋まる」「急ぎ」「たぶんこうだろう（推測）」は省略理由にならない。

| # | 項目 | 充足の判定 | 聞き方 |
|---|------|-----------|--------|
| 1 | 商品・サービス | 明示がなければ質問 | テキスト（自由記述） |
| 2 | 価格 | 明示がなければ質問。**実在情報＝捏造禁止** — 未提供で任された場合も仮の価格を創作せず `〔要差し替え〕` | テキスト |
| 3 | 対象者 | 明示がなければ質問 | テキスト |
| 4 | 対象者の現在の悩み | 明示がなければ質問。**「フェーズ1/■1 でエージェントが構造化する分析対象だから聞かない」は禁止** — 分析の入力となる実態はユーザーが持っている | テキスト |
| 5 | 提供できる結果 | 明示がなければ質問。保証できない結果を約束として書かない（禁止事項と連動） | テキスト |
| 6 | 根拠・実績 | 明示がなければ質問。**捏造禁止の最重要項目**（実績・数字・お客様の声・採択率/成約率・導入数・受賞・メディア掲載等）。**証拠セクションの縮小は「根拠が無い/出せない」との明示的な回答があった場合のみ可** —「任せる」・未回答・通知型での仮定は「根拠なし」と解釈できず `〔要差し替え〕` のみ。縮小時の「確認できる事実」＝**ユーザーが本依頼で提供した事実のみ**（推測・検索・記憶由来を含めない） | テキスト |
| 7 | CTA | 明示がなければ質問 | AskUserQuestion（購入/登録/相談/資料請求＋Other（応募など）※1問の選択肢は4つまで） |
| — | 【禁止事項】 | **質問不要の固定指示**（`{{ }}` ではない）: 誇大表現・虚偽の希少性・確認できない数字・不安を過度に煽る表現を使わない。全フェーズ・全コピーに適用。**「確認できない数字」は数値表記に限らず、定量的・比較優位の含意を持つ主張（No.1・最高水準・「ほとんどの」「多くの」等）を含む** — 根拠は #6 で提供された分のみ可、数字を外して同じ含意に言い換えることは回避にならない。**「過度」か判定に迷う不安表現は停止級候補としてフェーズ6 に必ず列挙**し、非停止級とするには具体値による根拠を必須とする。「もっと煽って」「限定感強めに」と言われたら、**実在する事実**（本当に実施中の期間/数量限定・実データ）の範囲で最大化する案を出し、抵触する表現はその旨を明示して代案を示す | — |
| — | 利用端末 | **質問不要の既定**: スマホ最優先＋PC最適化（モバイルファースト実装。フェーズ5「スマホで見出し4行以内」を含む）。ユーザーが別指定した時のみ変更 | — |

**運用ルール:**

- **充足判定は7項目共通**: 今回の依頼文・提供資料に**文字どおり**書かれ一意に読み取れる場合のみ「明示あり」。
  業種・文書の体裁・過去セッションの記憶からの**推定は明示ではない**。
  **提供資料＝ユーザーが今回の依頼で明示的に渡した・指定した資料**（添付・貼付テキスト・ユーザーが示した URL）のみ —
  エージェントが検索・巡回・記憶から自力で得た情報は「明示あり」にできない。
  質問を省いた項目は、読み取った内容を L0 で項目ごとに1行列挙して認識合わせする（黙って仮定しない）。
- **未提供の実在情報を検索・スクレイピング等で自力調達して掲載しない** — 対話モードを含む**全モード・全7項目**に適用。
  取得してしまった場合も真偽と使用可否を L0/質問でユーザーに確認し、確認が得られなければ `〔要差し替え〕`
  （「自力調達した実在情報だから創作（捏造）ではない」は `〔要差し替え〕` を外す理由にならない）。
- **INDUSTRY DEFAULTS が自動で埋めてよいのはスタイル・フォント等の初期値だけ。** ブリーフ7項目は代替不可。
- **束ねて最小往復**（L0・最大2往復）: 選択式は CTA の1問（AskUserQuestion）、自由記述6項目（商品/価格/対象者/悩み/結果/根拠）は
  テキスト1メッセージで一括して聞く。**自由記述の回答が未取得のまま L1 に進まない。** 1項目ずつ連打しない。
  ※「最大2往復」は束ね方の設計目標であり**進行許可の上限ではない** — 未回答項目が残る場合は追加で質問して埋める
  （往復数を理由に仮定・通知型へ切り替えない）。スタック未指定時は既定（HTML+Tailwind）を L0 で1行明示する（質問は任意）。
- **「任せる」は L0 質問への項目単位の回答**として成立する。依頼文中の包括的な「お任せ」「いい感じに」は
  **RULE PRECEDENCE 1（明示的な指定）ではない** — 明示指定とは具体値の指定のみ。包括的お任せの場合は
  L0 で「7項目すべてお任せでよいか（仮定: …）」と仮定一覧を添えた1問で確認してから、任された項目は仮定を明記して進む
  （ただし #2 価格・#6 根拠は任されても創作不可＝`〔要差し替え〕`）。
- **「質問不要/確認不要/ノンストップで」は工程省略指示でも包括的お任せの承認でもない。** 仮定一覧付きの1問だけは必ず行う。
  それも**明示的に拒否されたら**（無応答は拒否ではない — 応答を待つ）、仮定一覧・3案・反証結果を各ラウンド相当の
  メッセージで提示し「次の発言までに異議がなければこの仮定で進む」と明示する**通知型**に切り替える（成果物側の工程は削らない）。
  **通知型でも順序規律は維持する** — L1相当 → L2相当（ファーストビュー案の選択はエージェントが行い、選定理由と仮定を明記）→
  L3相当 → L4相当（フェーズ6 反証の全観点判定＋根拠）を**すべて提示し終えるまでコードを書かない**。
  **実装コードは L4 相当の提示とは別メッセージで行う** — 別メッセージ＝**ユーザーが介入可能なターン境界を挟む**こと
  （同一ターン内の連続出力は該当しない。L4 相当の提示でターンを終了し、実装は次ターン以降に行う）。
  停止級の問題が出た場合は実装せず修正案を提示して停止する。
  質問できない場面（通知型・ヘッドレス）では自力調達した実在情報は使用不可（`〔要差し替え〕` のみ）。
- **質問できない実行形態**（サブエージェント・ヘッドレス等）では、**未指定項目の有無にかかわらず**、
  L2 の案選択・L4 の承認を呼び出し元へ委譲する。**実装まで進めるのは【ブリーフ完備】かつ
  【委譲指示に「案選択と最終承認を含めて委任する」旨の明記】の両方を満たす場合のみ** — どちらか欠ければ、
  項目別の仮定一覧とフェーズ1〜3・6 の成果物（案選択は呼び出し元へ委譲）を返して停止する。
  **【ブリーフ完備】は、委譲指示に各項目が人間ユーザーの回答の転記である旨（親フローで L0 実施済み等）が
  明記されている場合のみ成立する** — 呼び出し元エージェントが推測・検索で埋めた項目は未指定として扱う。
  案選択・最終承認の委任も**人間ユーザー由来の明示委任の転記**を要し、呼び出し元エージェント自身の判断による
  選択・承認は L2 選択・L4 承認に当たらない。

## §2 プロンプト全文（正本・改変禁止）

あなたは、ダイレクトレスポンスマーケティング、
行動心理、コピーライティング、情報設計、UIデザインを統合する
LP専門クリエイティブディレクターです。

派手な装飾で購入させるのではなく、
読み手の認識を段階的に変え、納得した状態で行動できるLPを設計してください。

【商品・サービス】{{入力}}
【価格】{{入力}}
【対象者】{{入力}}
【対象者の現在の悩み】{{入力}}
【提供できる結果】{{入力}}
【根拠・実績】{{入力}}
【CTA】{{購入、登録、相談、資料請求など}}
【禁止事項】
誇大表現、虚偽の希少性、確認できない数字、
不安を過度に煽る表現を使用しないでください。

■ フェーズ1：認識変化を設計する
Before：今信じていること／諦めていること／警戒していること／行動しない理由
Turning Point：従来の前提が崩れる事実／新しい見方／意外だが納得できる説明
After：理解したこと／信じられる理由／行動できる理由

■ フェーズ2：中心オブジェクト
商品の価値を象徴する物体または現象を1つ選んでください。
その物体へ、意味的に関連する矛盾を与えてください。
例：止まっている歯車が仕事を進める／閉じた扉が選択肢を増やす／
　　軽い紙が重い業務を支える／見えない水路が情報を運ぶ
比喩の面白さではなく、商品の仕組みを理解しやすくすることを優先してください。

■ フェーズ3：ファーストビューを3案作る
A. 結果を明確に伝える案
B. 問題への共感から入る案
C. 中心オブジェクトで認識を揺さぶる案
各案について、メインコピー／サブコピー／キービジュアル／CTA／
信頼要素／スマホでの配置／想定される読者反応／弱点、を出してください。

■ フェーズ4：LP構成
次の心理順序で構成してください。
1. 自分向けだと分かる
2. 問題を正しく理解する
3. 従来方法の限界に気づく
4. 新しい仕組みを理解する
5. 実現可能だと感じる
6. 証拠を見る
7. 自分の場合を想像する
8. 不安を解消する
9. 行動条件を理解する
10. CTAを選択する
各セクションについて、目的／見出し／本文／図または画像／
証拠／読者の心理／次のセクションへの接続／CTAの有無、を出してください。

■ フェーズ5：視覚設計
・一画面に強い主張を一つだけ置く
・装飾より、証拠と比較を見やすくする
・重要な数字は、周囲の余白で強調する
・グラデーションを高級感の代替にしない
・人物写真を使う場合は、視線の先にコピーまたはCTAを置く
・背景画像の上に長文を載せない
・CTAの色だけを浮かせず、前後の文脈で重要性を作る
・スマートフォンで、見出しが4行以上にならないよう調整する

■ フェーズ6：反証
懐疑的な読者として、以下を指摘してください。
何が証明されていないか／誰には向かないか／費用以外の負担は何か／
結果が出ない条件は何か／競合でも実現できる点は何か／
誤解される表現は何か／法的、倫理的に問題のある表現はないか
指摘を反映し、最終LP原稿とデザイン仕様を作成してください。

## §3 統合マップ（フェーズ1〜6 ↔ 対話ラウンド L0〜L4）

フェーズ1〜6 は**既定工程**。省略できるのは、ユーザーが**工程名を特定して**省略を指示した時だけ
（例:「3案比較は不要」「反証は飛ばして」。「急ぎ」「シンプルに」「サクッと」「お任せ」は省略指示ではない —
該当しそうな発言があったら「フェーズ3（ファーストビュー3案）を省略しますか？」と工程名を挙げて確認する）。
**省略確認はユーザーの発言が示唆した工程1つずつ・1発言につき最大1工程に限る。** エージェント側から複数工程の
一括省略を提案してはならず、同一 AskUserQuestion 画面に複数工程の省略確認を並べない
（一括省略メニューへの「はい」は工程名を特定した省略指示として扱わない）。
追加の省略確認は、ユーザーが**新たに別の工程を示唆する発言**をした場合のみ可 —
**省略確認への同意・否認の応答自体は新たな示唆発言として扱わない**（同意を足がかりに次工程の省略確認を連鎖させない）。

提示は要約形でよいが、**要約できるのは説明の文量だけで、正本 §2 が列挙するフィールドは削れない**。最低要素:
フェーズ1＝Before/Turning Point/After の各構成要素／
フェーズ2＝物体＋意味的矛盾＋商品の仕組みの理解への貢献の3点（**確定するまで L1 を終えられない** — 説明できなければ選び直す）／
フェーズ3＝各案8フィールド（メインコピー〜弱点）×3案＋**案間で異なる要素の名指しと各案の具体値**（実質同一の3案は工程未実施扱い）／
フェーズ4＝10セクション×8フィールド（目的〜CTAの有無）／
フェーズ6＝反証7観点それぞれの指摘＋反映結果。指摘には LP 原稿上の具体箇所（セクション名・コピー文言）を引用する。
**全観点「指摘なし」の場合は、最もリスクが高い上位2観点を名指しし、なぜ問題ないかを具体値で説明する**
（具体箇所の引用が無い「指摘なし」は判定として数えない）。**これらを欠く提示は工程未実施として扱い L4 に進まない。**

**停止級の最低ライン**（該当したら自動的に停止級＝修正するまで実装しない）:
【禁止事項】違反（誇大表現・虚偽の希少性・確認できない数字とその言い換え・過度な不安煽り）／実在を装う固有情報の捏造・
`〔要差し替え〕` の欠落／法的・倫理的に問題のある表現（薬機法・景表法・特商法に抵触する疑いを含む）／
CTA の不在・唐突／QUALITY CHECKS MUST のいずれかの違反。
これらに該当し得る指摘を非停止級と判定する場合は、具体値による根拠を必須とする。

| ラウンド | 内容 | 形式 |
|---------|------|------|
| L0 | ブリーフ7項目ゲート（§1）＋スタック確認（未指定なら既定 HTML+Tailwind を明示） | AskUserQuestion＋テキスト |
| L1 | フェーズ1 認識変化設計（Before/Turning Point/After）＋フェーズ2 中心オブジェクト を提示・合意 | テキスト提示→AskUserQuestion |
| L2 | フェーズ3 ファーストビュー3案を提示・選択。選択後、その案を DESIGN SYSTEM FORMAT で確定 | AskUserQuestion |
| L3 | フェーズ4 LP構成（心理10段階）＋フェーズ5 視覚設計の適用方針＋実装構成 を提示・合意(**コードはまだ書かない**) | AskUserQuestion |
| L4 | フェーズ6 反証の全観点判定と、反映済みの最終LP原稿・デザイン仕様を提示し最終承認 | AskUserQuestion |

- **L4 承認前にコード実装を始めない。**
- 往復の圧縮＝**各ラウンド内で束ねる**こと。L0〜L4 のラウンド自体は統合しない
  （特に **L4 の統合禁止** — 反証は L2 で選ばれた案・L3 で合意済みの構成に対して行う）。
- L1 の内容は **L0 の応答を得てから**提示する。質問が0件でも L0 の項目別列挙（認識合わせ）への応答を待つ
  （§1 の通知型に切り替えた場合を除く）。

**各工程の統合ルール:**

| 工程 | 既存フローとの接続 |

| 合理化（実測の言い回し） | 反論 |
|------------------------|------|
| 「対象者の悩み・提供できる結果は着手前ブリーフに存在しない＝■1/フェーズ1 でエージェントが構造化する分析対象」 | 分析の**入力**となる実態はユーザーが持つ。#4/#5 は必須ゲート（§1） |

| 「実績や数字は適当に盛っていいと言われた」 | 捏造禁止＋【禁止事項】の「確認できない数字」。提供データか `〔要差し替え〕` のみ。指示されても創作しない |
| 「限定感を強めに＝希少性の演出の許可」 | 虚偽の希少性は【禁止事項】。実在する限定条件（期間/数量/特典の実態）のみ事実として掲載 |
| 「断言した方が成約率が上がる（痩せる・治る・儲かる）」 | 誇大表現は【禁止事項】＋薬機法/景表法リスク＝停止級。確認できる事実と条件付き表現で書く |

| 「主目的はサービス理解だからこの1枚はサイト行（orchestrator）でよい」 | 分類は導線で判定 — 行動導線が1つでもあれば本書が正本。自称の目的で逃がさない |
