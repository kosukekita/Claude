# Handoff

新しいエージェントが続きを実行できるよう、現在の会話を要約した**引き継ぎ文書**を書く。

## 保存先（OS の一時ディレクトリ — リポジトリには絶対に置かない）

ワークスペース／git リポジトリには置かない。OS の一時ディレクトリに保存する。実パスの解決は各 shell に任せてよいが、**ツール引数（Write/Read 等）へ渡すときは必ずフォワードスラッシュの正規形**にする:

- **Windows:** `C:/Users/u8792/AppData/Local/Temp/handoff-<topic>.md`
- **Linux / Mac:** `${TMPDIR:-/tmp}/handoff-<topic>.md`

> Git Bash の `/c/...` や PowerShell の `\` 区切り（`$env:TEMP\...`）は、**そのままツール引数に使わず**フォワードスラッシュへ正規化してから渡す。バックスラッシュは `\U`（= `\u` + 続く文字）が Unicode エスケープ扱いになり、静かに別の場所を指す既知バグがある。

これは「スクラッチ .md をリポに散らかさない」という既存方針の補強でもある。

## 文書に含めるもの

1. **要点の圧縮** — このセッションで決めたこと・進捗・続行に必要な文脈を抽出。網羅ではなく「次の人が動ける最小限」。
2. **重複させない（参照する）** — PRD・plan.md・ADR・issue・コミット・差分など既存成果物の内容は再掲しない。**パスや URL でリンク**する（古いコピーが分岐するのを防ぐ）。引数で次セッションの焦点が渡されたら、それに合わせて要約を調整する。
3. **"推奨スキル" セクション** — 次のエージェントが呼ぶべきスキルを列挙（例: `systematic-debugging`, `ai-prediction-model`）。スキル認識をセッション境界を越えて伝播させる。
4. **記憶との整合** — 恒久的に残すべき学び・決定があれば、引き継ぎ文書とは別に auto-memory（`projects/<スラグ>/memory/`）または pCloud プロジェクトの `./.claude-memory/` に保存し、`MEMORY.md` 索引を更新（→ `cross-agent-memory` スキル）。引き継ぎ文書からは該当する記憶ファイル名を相互参照する。一時文書（揮発）と恒久記憶（永続）を取り違えない。

## 永続化する前に墨消し（必須）

ファイルに書き出す前に、機微情報を伏字にする:

- API キー・トークン・パスワード・OAuth シークレット
- 個人情報（PII）
- **本環境で既知の平文機密**: TotalSegmentator のライセンス番号（`config.json` に平文）、各種 API キー。これらは引き継ぎ文書に転記しない。
- **文字化け・サロゲート対策**: パスや本文に孤立サロゲートや非 UTF-8 バイトを混ぜない（焼き付くと毎ターン API 400 を誘発する）。ASCII / 妥当な UTF-8 のパス表記に正規化してから書く。

## 言語

引き継ぎ文書は**日本語**で書く（CLAUDE.md 規則）。ただしコード・エラー文・絶対パスは原文どおり。
